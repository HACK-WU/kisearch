# ai-codekb-memory AI 知识与记忆管理规则

> **对话开始时首先检查本规则。**
> **前提**：AGENTS.md 已初始化完成（由用户通过 `agents-md-init` skill 手动触发，本规则不执行初始化）。

---

## AGENTS.md —— 临时记忆铁律

> **AI 在对话过程中必须使用 `AGENTS.md` 文件作为临时记忆文件（working memory），主动记录相关内容。**
> 这不是可选动作，而是默认行为：对话中产生的新信息（架构认知、需求进度、关键代码、技术决策、问题追踪、用户偏好），AI 应主动写入 AGENTS.md 对应章节，**不依赖用户提示或确认**。
>
> **注意**：AGENTS.md 承载的是"临时记忆 + 索引缓存 + 用户画像 + 近期工作"；**详细项目知识仍走 ki 记忆**（见"记忆系统分工"），AGENTS.md 只记录索引、画像、进度与有价值的临时要点，避免膨胀。

**强制记录时机**：

| 时机 | 记录到 |
|------|--------|
| 理解/分析项目架构、模块关系 | AGENTS.md"项目架构"章节 |
| 理解/拆分需求、更新进度 | AGENTS.md"近期工作"章节 |
| 阅读/修改关键代码（核心函数/配置/API） | AGENTS.md"关键代码"章节（详细知识可再沉淀到 ki） |
| 调试/解决问题、记录已知坑 | AGENTS.md"问题追踪"章节 |
| 做出技术选型/设计决策 | AGENTS.md"决策记录"章节 |
| 用户表达偏好、项目约定 | AGENTS.md"用户画像"章节 |

**更新原则**：① 写入前先查重，已存在相同信息则更新而非新增；② 版本更新时保留历史；③ 定期清理过期条目（配合"归档机制"）；④ 敏感信息（密码/密钥/隐私）脱敏后记录。

## 0. 速览

> **第一性原则：遇事不决 ki-search。** 遇到任何不知道的问题、任何不知道的信息、任何不确定的内容，**不要自己猜、不要凭记忆答**，直接上 ki-search 检索。这是默认动作，不是备选方案。

```
对话开始 → scope 已知?
  ├─ 是 → 读取 AGENTS.md 用户画像/近期工作，按需加载 ki-search
  └─ 否 → 暂停问用户

遇到不知道的问题/信息 → 直接 ki-search（遇事不决 ki-search）
查询（读） → 引用 ki-search 四步走
沉淀（写） → 按本规则"自动沉淀"执行

访问 AGENTS.md"近期工作"? → 检查过期条目（>7天），移入项目根目录 archive.md
```

## 记忆系统分工

| 系统 | 适用 | 典型内容 | 优势 |
|------|------|----------|------|
| **平台内置记忆** (`update_memory`) | 简洁、通用、跨项目、高频、稳定 | 沟通偏好、通用行为规则、工具习惯 | 自动注入上下文，零查询成本 |
| **ki 记忆** (`ki_sync_relation` / MCP) | 详细、项目特定、结构化、有时效 | 项目背景、架构决策、代码知识、踩坑点 | Group 树组织、热区/语义检索、归档机制 |
| **AGENTS.md** | 临时记忆 + 项目索引缓存 + 用户画像 + 近期工作 | 临时记忆（架构/需求/决策/问题）、项目记忆索引、用户偏好、需求进度 | 随对话注入，零查询成本 |

**选择判断**：简洁+通用+跨项目 → 平台记忆；详细/项目特定/需结构化 → ki 记忆；临时记忆/用户画像/近期工作/索引缓存 → AGENTS.md（见"临时记忆铁律"）。ki 记忆内部：代码知识 → `ki-search`（`${scope}`，**只读**）；项目上下文与代码片段 → `${scope}-memory`。

> **偏好路由判据**：跨项目工具偏好（编辑器/包管理器/终端）→ **平台记忆**；项目特有偏好（本项目的命名约定/分支策略）→ **AGENTS.md 用户画像**。

## 查询 vs 沉淀（核心分工）

| 动作 | 走哪 | 说明 |
|------|------|------|
| **查询（读）** | 加载 `ki-search` | 四步走：① `ki_search(${scope}-memory, limit:4, threshold:0.02)` → ② `ki_get_module_info` 索引兜底 → ③ `ki_search(${scope})` 宏观兜底 → ④ 回问用户。覆盖代码知识、项目记忆、代码片段的全部检索，**本规则不再重复定义查询流程** |
| **沉淀（写）** | 本规则"自动沉淀" | 对话中发现新信息时，按触发条件写入 `${scope}-memory` 或 AGENTS.md（见下节） |
| **知识库修改** | `ki-search` §5 | `${scope}` 默认**只读**；仅当发现知识库与实际代码不符且获得用户**明确授权**后，才可写入 |

> **记忆查询统一由 `ki-search` 四步走负责**，AI 需要读任何知识/记忆时直接引用，不要在本规则中另起查询流程。
>
> **遇事不决 ki-search**：无论读代码、查记忆、理解架构、排查问题，只要有任何"不知道/不确定"的信息，**第一动作就是 `ki_search`**，不要凭记忆或经验作答。
>
> **代码相关先 ki-search**：遇到代码相关问题（代码在哪、怎么实现、架构、API、bug、审查），**同样先 `ki_search`**——记忆里很可能已有该代码的知识（踩坑点、关键逻辑、工具函数），先看有没有现成知识再看代码，不要一上来就 grep/读文件。

### ki-search 查询指导（提高检索效率）

**查询词构造**：推荐使用「**语义描述 + 空格 + 多个关键代码符号**」的组合进行搜索：

```
<语义描述> <关键代码符号1> <关键代码符号2> ...
```

- **语义描述**：用自然语言描述要解决的问题/功能（如"登录鉴权流程"、"数据导入中断恢复"）
- **关键代码符号**：追加可能相关的类名/函数名/变量名（如 `AuthService`、`importDocument`），多个符号用空格分隔，让语义检索与符号匹配互补，提升召回精度

**检索不满意时的调整策略**：

| 情况 | 调整方式 |
|------|----------|
| 结果不相关 | 调整语义描述措辞（换关键词、补充限定词），或更换/增减关键代码符号 |
| 结果太少/缺失 | 适当提高 `limit` 获取更多内容；或放宽 `threshold` |
| 结果仍不满意 | 依次走 `ki-search` 四步走的后续兜底（`ki_get_module_info` → 宏观 `ki_search` → 回问用户） |

## AGENTS.md 缓存机制（运行期维护）

> **AGENTS.md 是 AI AGENT 的项目记忆文件，位于项目根目录。默认已初始化；本规则只负责运行期维护。**

**缓存内容**：
1. **临时记忆**：对话中产生的架构认知、需求进度、关键代码、技术决策、问题追踪（见"临时记忆铁律"，AI 主动写入）
2. **项目记忆索引**：`${scope}-memory` 的 Group 结构（含通用记忆片段）、热门 Relation
3. **用户画像**：AGENTS.md"用户画像"章节（不经 ki）
4. **近期工作**：AGENTS.md"近期工作"章节（最近需求/进度，不经 ki）
5. **新需求记录**：AGENTS.md"近期工作"章节

> **代码知识库（`${scope}`）索引不写入 AGENTS.md**，查询代码知识时经 `ki-search` 直连 ki。

**运行期维护**：

| 时机 | 动作 |
|------|------|
| 写入 `${scope}-memory` 新 Group/Relation 后 | 刷新 AGENTS.md"项目记忆索引"章节 |
| 新需求出现 / 用户偏好变化 | 更新 AGENTS.md 对应章节 |
| 近期工作超 7 天 | 移入项目根目录 archive.md |
| 跨会话首次对话 | **强制重拉** `${scope}-memory` 全景（不依赖上次会话缓存） |

> 完整模板与初始化/增量流程见 `agents-md-init` skill（用户手动触发）。
> **AGENTS.md 缺失时（新项目未初始化）**：暂停记忆维护动作，先提示用户通过 `agents-md-init` 初始化后再继续；未初始化前不写记忆。

## 自动沉淀：写入记忆

> **AI 必须主动识别并自动记录，不得依赖人工提示或确认。**

### 触发条件

| 信息类型 | 触发信号 | 记录位置 |
|----------|----------|----------|
| 项目信息 | 用户陈述项目事实 | `${scope}-memory` |
| 踩坑经验 | 问题与解决方案 | `${scope}-memory` / 项目踩坑点 |
| 代码要点 | 工具函数/关键逻辑/数据模型/API等 | `${scope}-memory`（工具库/通用记忆片段等） |
| 需求/进度 | 提到要做的事或完成情况 | AGENTS.md"近期工作"章节 |
| 用户偏好 | 表达个人倾向 | AGENTS.md"用户画像"章节 |
| 记忆失实 | 发现项目记忆与实际代码信息不一致（代码已变更/记忆过期） | `${scope}-memory`（**更新**对应 Relation，非追加） |

> **记忆失实处理边界**：更新动作仅针对 `${scope}-memory`（项目记忆），**主动更新**即可；`${scope}` 知识库与实际代码不符时仍按"禁忌 13"执行——需用户**明确授权**后方可写入，不得擅自修改。

**写入方式**：项目记忆/代码片段 → 单条（1~2 条）用 `ki_sync_relation`；**批量（≥3 条）用 `ki_bulk_sync_relation` 批量写入（一次 embed + 一次向量写入，比多次逐条调用快 N 倍）**。**批量时建议分批调用，每批 ≤5 条**（MCP 单次 `items` 硬上限 50 条）——一次性组织大量文档数据耗时、占上下文、易出错，分批次服务端总耗时几乎不变但组织成本更低、单批失败只重试该批。超长 >1000 字符会收到警告，建议拆分。用户画像/近期工作 → 直接更新 AGENTS.md（覆盖/追加）；写入后刷新缓存。

**近期工作（AGENTS.md）格式**：

```
最近需求:
- [YYYY-MM-DD] 需求描述（1-2句）

进度:
- 进行中: [YYYY-MM-DD] 🔄 描述
- 已完成: [YYYY-MM-DD] ✅ 描述
```

## 归档机制

| 数据 | 位置 | 保留规则 | 归档方式 |
|------|------|----------|----------|
| 近期工作（最近需求/已完成进度） | AGENTS.md"近期工作"章节 | 仅保留 7 天内 | 超期移入项目根目录 `archive.md` |
| 近期工作（进行中进度） | AGENTS.md"近期工作"章节 | 永久保留 | 不归档 |
| 当前状态 | ki `${scope}-memory` | 超 30 天标记过期 | 移到 `archive.md` |
| 其他 Group（含代码片段） | ki `${scope}-memory` | 永久保留 | 不归档 |

**每次访问 AGENTS.md"近期工作"章节或"当前状态"时**检查并归档。统一流程（数据源分 AGENTS.md / ki）：

1. 读取对应章节/Relation，解析 `[YYYY-MM-DD]` 条目
2. 标记过期（近期工作 >7 天；当前状态 >30 天；进行中进度永久保留）
3. 活跃条目覆盖写回（AGENTS.md 或 `ki_sync_relation`）
4. 过期条目追加到项目根目录 `archive.md`（按日期分组，不删除历史，首次自动创建）
5. ki 数据源需 `ki_query_group(mode: "full")` 刷新缓存

## 代码片段记忆

代码要点（工具函数、关键执行逻辑、核心流程、数据模型、API 调用、配置模板、错误处理）写入 `${scope}-memory` 对应 Group。

### 存储结构

```
# 预定义 Group（优先归类）
工具库/          ← 通用工具函数、脚本（Relation: "日期时间"、"字符串处理"、"通用"）
项目踩坑点/      ← 已知问题、注意事项（Relation: "XX库兼容问题"、"通用"）
部署运维/        ← 配置模板、部署流程（Relation: "构建配置"、"通用"）
# 兜底 + 业务功能 Group
通用记忆片段/    ← 无法归入预定义分类时用，与工具库平级
├── 关键逻辑/    ← Relation: "认证流程"、"告警收敛"...
├── 数据模型/    ← Relation: "通用"
├── API 调用/    ← Relation: "通用"
├── 配置模板/    ← Relation: "通用"
└── 错误处理/    ← Relation: "通用"
```

**分类原则**：优先归入预定义 Group；无匹配用"通用记忆片段"兜底并按业务功能/代码类型细分；单 Relation 超 10 个片段时拆分；AI 可根据项目实际自主扩展。创建时先判断"片段属于哪个业务功能"，有明确归属走功能分类，纯通用走类型分类。

> **写入边界（防混淆）**：`团队约定`/`Commit 规范` 等**项目级约定** → `${scope}-memory`（团队约定）；`lint 规则`/`代码通用约定` 等**纯代码约定** → `${scope}`（ki-search 白名单"项目通用约定"）。不确定时默认走 `${scope}-memory`。

### 片段格式铁律

> **第 1 行必须是纯文字描述**（1-2 句，说明"做什么、怎么用"），**禁止 `###` 标题开头，禁止 YAML 元数据块**（`---` frontmatter，如 name/description 字段）——描述承载语义，提升 `ki_search` 检索精度；标题（符号名）语义量低且干扰向量化，YAML 元数据块为结构数据同样干扰语义检索。必填字段：`符号`（类/方法签名）、`位置`（文件路径，**不含行号**——行号随代码变动失效）。relation 名承担分类定位，片段内不再需要标题。

**工具函数类**：

```markdown
将 Date 对象格式化为 yyyy-MM-dd 字符串的通用工具函数，支持自定义分隔符。
- 符号: `DateUtils.formatDate(date: Date, separator?: string): string`
- 位置: `src/utils/date.ts`
- 用法: `DateUtils.formatDate(new Date())` → `"2026-06-23"`
```

**关键逻辑/核心流程类**：

```markdown
告警收敛流程：按策略匹配收敛规则，将同维度告警合并到同一收敛组，达到阈值后触发通知并重置计数器。
- 入口: `AlertConvergenceService.converge(alert)`
- 位置: `src/alert/convergence.ts`
- 核心步骤:
  1. 按策略匹配收敛规则（时间段/维度/阈值）
  2. 同维度告警合并到同一收敛组
  3. 达到阈值后触发通知，重置计数器
- 关键点: 收敛窗口内同一维度只发一次通知；阈值按策略可配置
```

### 写入片段

- 追加写入（单条）：`ki_sync_relation(scope: "${scope}-memory", group: "工具库", relation: "日期时间", module_info: "<描述+符号+位置>")`，新片段追加到已有 Relation 末尾
- **批量写入（≥3 条或多文档）**：用 `ki_bulk_sync_relation(scope: "${scope}-memory", items: [{ group, relation, module_info, tags? }])`，一次 embed + 一次向量写入，比多次逐条调用快 N 倍；**建议分批调用，每批 ≤5 条**（一次性组织大量文档耗时易错，分批服务端总耗时几乎不变）
- **写入前查重**：先 `ki_get_module_info` 获取 Relation 当前内容，若已存在相同 `符号` 的片段 → 更新而非追加
- 写入后刷新缓存：`ki_query_group(scope: "${scope}-memory", mode: "full")`

### 查询片段

查询统一走 `ki-search` 四步走（① `ki_search(${scope}-memory)` 语义检索已覆盖片段记忆）。

**编码前自动查询**：AI 编写代码前，主动查询片段记忆是否有可复用工具。

### 初始化：从代码构建片段记忆

**触发信号**：用户给出代码文件/文件夹并明确要求提取片段（如"根据这些内容构建记忆"、"把这个文件夹里的工具函数记录下来"）。

**流程**：① 扫描代码识别可复用函数/类/方法 → ② 分类判断（预定义 Group 优先，无匹配走通用记忆片段）→ ③ 生成片段（描述+符号+位置）→ ④ **用 `ki_bulk_sync_relation` 分批写入**（一次 embed + 一次向量写入；建议每批 ≤5 条，分多批调用）→ ⑤ 刷新缓存。

**识别规则**：工具函数（无副作用、通用性强）→ 工具库；核心执行逻辑（主流程/状态机）→ 关键逻辑；interface/type/class → 数据模型；HTTP 封装 → API 调用；配置/枚举/常量 → 配置模板；错误处理/降级 → 错误处理。**不记录**：简单 getter/setter、组件模板（走知识库）、一次性临时代码、纯配置值。

### 与知识库的边界

| | 代码片段记忆 | ki-search |
|---|-------------|--------------|
| 内容 | 代码级要点（函数、关键流程、数据模型等） | 架构知识、模块职责、API 设计 |
| 粒度 | 函数/方法/核心流程级别 | 模块/系统级别 |
| 存储 | `${scope}-memory` 下按内容归类 | `${scope}` |
| 查询 | 直接取原文（列表式） | 语义检索优先（ki_search） |

## 会话结束收尾

> **检测到以下信号时，AI 应主动执行记忆更新，表示当前阶段即将结束、进入下一阶段。**

**触发信号**（用户说）："好"/"OK"/"可以"/"没问题"（确认结果）、"记录到文档"/"保存"（要求记录）、"开始实施"/"开始写代码"（进入实施）、"下一个"/"继续"（切话题）。

**收尾动作**：
```
□ 是否有未记录的新需求？→ 写入 AGENTS.md"近期工作"章节
□ 是否有未记录的代码要点？→ 写入 ${scope}-memory（见"代码片段记忆"）
□ 是否有进度变化？→ 更新 AGENTS.md"近期工作"章节
□ 索引是否有变更？→ 刷新 AGENTS.md 项目记忆索引
□ 近期工作是否超过 7 天？→ 【强制】检查并触发归档（见"归档机制"），不得跳过
```

> 不需要等用户说"结束"才执行，而是在**对话自然转折点主动执行**。

## 禁忌

| # | 红线 |
|---|------|
| 🔴 1 | **将详细项目知识存入平台内置记忆**（代码知识、架构决策等必须走 ki） |
| 🔴 2 | **将简洁通用偏好存入 ki**（沟通语言、通用规则等用平台记忆） |
| 🔴 3 | `${scope}` 未确认就加载 SKILL 或执行 ki 命令 |
| 🔴 4 | Skill 不存在时仍继续执行 ki 命令（应提示用户安装 kisearch） |
| 🔴 5 | **对 ki scope 使用 memory MCP 存取**（统一用 ki MCP 工具） |
| 🔴 6 | **用户画像/需求进度写入 ki scope**（应存 AGENTS.md 对应章节） |
| 🔴 7 | **忽略 AGENTS.md 缓存维护**（对话开始检查、索引变更后更新、跨会话重拉全景，缺一不可） |
| 🔴 8 | **依赖人工提示记录需求**（AI 必须主动识别新需求信号并自动记录） |
| 🔴 9 | **近期工作超 7 天不归档**（必须移入 archive.md，保持 AGENTS.md 简洁） |
| 🔴 10 | 近期工作条目不带日期前缀 `[YYYY-MM-DD]` 或超过 1-2 句 |
| 🔴 11 | 删除过期条目而非归档 |
| 🔴 12 | 片段违反格式铁律（开头非描述、带 YAML 元数据块/标题、缺符号/位置、位置带行号） |
| 🔴 13 | **未经用户明确授权修改 `${scope}` 知识库**（默认只读） |
| 🔴 14 | **遇到不知道的问题/信息时凭记忆猜、不查 ki-search**（遇事不决 ki-search，先搜再答） |
| 🔴 15 | **代码相关问题跳过 ki-search 直接 grep/读文件**（记忆里很可能已有该代码知识，一律先 ki-search） |
| 🔴 16 | **对话中产生新信息却不写入 AGENTS.md 临时记忆**（必须主动记录，见"临时记忆铁律"） |

> 例外：`ki-search` 的 `ki_search` 语义兜底不受规则5限制（ki MCP 内置向量工具）。平台内置记忆（`update_memory`）不写入 ki scope，也不受限。

## AGENTS.md 维护规范

- **文件大小**：不设硬性字节上限；通过"归档机制"兜底控制——过期条目（近期工作 >7 天、当前状态 >30 天）必须移入 archive.md，防止无限膨胀。若文件体积过大影响注入效率，可主动清理合并冗余条目
- **更新时机**：新需求 / 索引变更 / 用户偏好变化 / 每日检查
- **一致性**：发现不一致自动更新，无需用户确认
- **初始化**：AGENTS.md 的创建与结构更新由 `agents-md-init` skill 负责（用户手动触发），本规则不执行
