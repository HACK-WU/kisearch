## 🔑 语义一致性分析

**[M1]** 上游 messages 重复本轮 user —— **本轮已修**（本次变更的由来）

- 类型：实现与契约不一致（数据流守恒破坏）
- 涉及：`chat-routes.ts:813`（锁内落 user）↔ `tool-loop.ts:137`（无条件再 push）
- 实际做：上游 = `[...conv.messages(含本轮 user), userText]` → 本轮 user 出现 2 次 + 连续同角色

  故属于接线处缺契约；根因是"路由先落盘、tool-loop 再拼一次"的双重表达
- 建议方向：① tool-loop 侧守卫（**已采用**）② 路由传落盘前快照（需连带改 `messageIdFor` 的 id 计算，风险更大）
- 端到端证据：mock 上游捕获 `["system","user:第1轮","user:第1轮"]` → 修复后 `[...,"user:第2轮"]` 各一次

## 🟡 建议改进

**[P1-1] 跨两处的隐式不变量缺契约（已修）**
- 位置：`tool-loop.ts:140`（守卫）↔ `tool-loop.ts:452`（`splice(length-1, 0, …)`）
- 问题：splice 的插入位置依赖"返回数组末条恒为本轮 user"，此不变量**只存在于实现里**，
  无注释、无测试；未来有人把守卫改成位置判定（如"末条是 user 就跳过"）会静默把检索上下文插错位
- 修复：两处加**双向交叉引用注释** + 新增降级路径用例守护（工作项 1、2）

**[P1-2] 降级路径的上游形状零断言（已修）**
- 位置：`degradedPath` / `runPreRetrievalFallback`
- 问题：本文件此前只断言工具路径；降级路径的注入位置、本轮 user 唯一性无任何断言
- 修复：新增 `describe('多轮上下文 · 降级路径…')` 用例（断言末条不变量 + 注入紧邻 + 历史顺序 + system 最前）

**[P1-3] 降级路径注入 `role:'user'` 造成连续同角色（未修，需你定）**
- 位置：`tool-loop.ts:453` 与 `:456-459`（两处注入都用 `role:'user'`）
- 问题：注入项紧邻本轮 user（也是 `role:'user'`）→ 上游出现 `user,user` 连续同角色，
  **与本轮 P0 缺陷同一风险类**（部分 OpenAI 兼容上游会 400）。工具路径修完已无此问题，降级路径仍在
- 影响面：仅 `supportsTools=false` 上游 / 检索失败的降级链路（触发面窄，但一旦触发若上游严格则整条链路不可用）
- 建议方向：① 把注入项改成 `role:'system'`（语义上更贴"系统代跑检索的结果注入"，且天然消除连续同角色）；
  ② 或把注入内容**合并进本轮 user 消息**（单条 user，含上下文 + 提问）
- 为何本次未修：改动的是**提示词语义**（skill 反幻觉规则依赖注入位置与角色），属意图级变更，
  超出"最小修复"范围，且需一并回归 `data-flow` / `acceptance-sr01` 与真实上游

**[P1-4] `test/**` 不在任何 tsconfig，测试文件无类型检查（未修，需你定）**
- 证据：`tsconfig.json` `exclude: [..., "test"]`；`tsconfig.src.json` 只含 `src/zvec-engine/**`
- 实测：单独 typecheck `test/chat/*.test.ts` 有 **8 条存量错误**
  （`.delivery/mocks/*.mjs` 无声明文件 ×4、`data-flow` 隐式 any ×2、`@/` 别名需 web 的 tsconfig ×2）
- 影响：测试里的类型错误（如 fixture 与 `ConversationFile` 结构不符）**无人发现**；本次新增测试自身 0 错误
- 建议路径：新增 `tsconfig.test.json`（extends 根 + `include: ["test/**/*.ts"]` + `paths: {"@/*": ["web/src/*"]}`）
  + 给 `.delivery/mocks/*.mjs` 补 `.d.ts`，然后在 CI 加一步 `tsc -p tsconfig.test.json --noEmit`

**[P2-1] 守卫用「content 全等」判定，存在一处已接受的边界（已注明）**
- 位置：`tool-loop.ts:152`
- 边界：若某调用方传入的 conv **不含**本轮 user，而历史末条恰是**文本完全相同**的旧消息 → 本轮不再追加
- 评估：文本仍在（仅归属轮次不同），语义等价；路由三条链路都已先落盘，不会走到该形态
- 处置：在守卫注释中显式写明"已知限制（可接受）"，不额外加复杂度

**[P2-2] `!retrievalOk` 分支仍无断言（已记录）**
- 实测发现：把 embedding 指向不可达地址（`127.0.0.1:1`）**并不能**让 `retrievalOk=false` ——
  master `62b2190` 已把全文检索与 embedding 解耦，FTS 可用即判「检索可用」
- 结果：降级路径的「本次检索不可用」注入分支在本环境**不易自然触发**，该分支文案无断言
- 建议：交由 e2e / debug 造不可用场景补验；本用例已对**两支都成立的结构性不变量**做断言，不漏守护主目标
