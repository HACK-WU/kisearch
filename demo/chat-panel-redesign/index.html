思考2.1s

根因在落盘那一步，不在截断那一步。mode === 'edit' 与 regenerate 共用了 replaceLastAssistant1，而该函数是「向前找最后一条 assistant，再 splice 到末尾」——前置截断 truncateAfterAndEdit2 刚把尾部裁成 […, u']，它就顺着更早的 a1 把 u' 一起删了。

[u1, a1, u2'] --splice(1,2,a')--> [u1, a']   ← u2' 永久消失

判定依据要换成「末条本身是不是 assistant」：是就原位替换（messageCount 不变），否则直接追加。edit 则根本不该走这条路，走 appendMessage。

  • 改判后 regenerate 在「末条是 user」的同类吃掉中间消息缺陷一并消失
  • 两条分支各恰好消费 1 个 seq，与旧 splice 路径等价

从尾部向前找最后一条 assistant：

const lastAssistantIdx = (() => {
  for (let i = messages.length - 1; i >= 0; i--) {
    if (messages[i]!.role === 'assistant') return i;
  }
  return -1;
})();
messages.splice(lastAssistantIdx, messages.length - lastAssistantIdx, stamped);
