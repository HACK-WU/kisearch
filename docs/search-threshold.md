# 检索阈值（Threshold）怎么用

> **一句话**：它是**分数下限** —— 低于这个分数的结果直接不显示，其余照原顺序返回。
> 它**不参与打分、不改变排序**，只决定「哪些结果配出现」。

---

## 一、它做了什么

```text
检索出 N 条（每个库各自检索）
        ↓
逐条判断：这条的分数 ≥ 阈值 吗？
        ↓ 否 → 丢弃（不占返回名额）
        ↓ 是
按分数排序 → 取前 limit 条
```

三个要点：

- **先过滤、再截断**：设了阈值后，`limit` 是「过滤之后还剩多少条」的上限；
- **对每条命中生效**，不是对「全局前 N 名」生效；
- 默认值 `0` 表示**不过滤**（所有命中都能进）。

---

## 二、两种检索，两套分数

阈值的麻烦在于：**单库和多库的分数不是同一套算法，量级差十倍。**

| 检索范围 | 分数怎么算 | 常见区间 | 字面强 / 复制原文时 |
|---|---|---|---|
| **单库**（`--scope <一个库>`） | 向量名次分 + 字面名次分 × 字面倍率 | `0.016 ~ 0.033` | `0.1 ~ 0.35` |
| **多库 / 视图** | 语义相似度 + 字面分 ÷ 100 | `0.5 ~ 1.0`（只有字面命中时 `0.1 ~ 0.3`） | `2 ~ 5` |

同一篇文档、同一个查询，在两种模式下分数可能差 **20 倍以上**。举例（实测）：

| | 分数 |
|---|---|
| 该文档在**视图**里 | `0.83` |
| 该文档**单独查它所在库** | `0.024` |

所以：**阈值 0.6 在视图里是「筛掉弱相关」，在单库里是「一条都不剩」。**

---

## 三、该设多少

| 检索范围 | 想要的效果 | 建议阈值 |
|---|---|---|
| 多库 / 视图 | 不过滤 | `0` |
| 多库 / 视图 | 去掉明显不相关的 | `0.6 ~ 0.7` |
| 多库 / 视图 | 只要强相关 | `0.8` |
| 多库 / 视图 | 只要「正文命中原文」级别的 | `1.5` 以上（需命令行，页面滑块最高 1） |
| 单库 | 不过滤 | `0` |
| 单库 | 只留两路都靠前的 | `0.02 ~ 0.03` |
| 单库 | 只留字面强命中的 | `0.05 ~ 0.1`（多数查询会一条不剩） |

> 判断依据很简单：**先不设阈值跑一次，看第 1 名的分数有多高，再决定下限。**
> 不要凭经验跨模式套用。

---

## 四、⚠️ 切换检索范围前，先把阈值归零

页面上的阈值滑块**只有一个**，单库和多库共用。所以：

```text
在视图里设 0.6（好用）
        ↓ 切换 scope 到单库
单库常规最高分只有 0.033  →  结果全被过滤  →  页面空白
```

**操作建议**：切换 scope（尤其是从视图切到单库，或反过来）后，**先把阈值拖回 0**，重新看一眼第 1 名的分数，再设新的下限。

## 五、页面上能设的值有限

页面滑块的范围是 `0 ~ 1`、刻度 `0.01`，也就是只能取：

```text
0 · 0.01 · 0.02 · 0.03 · … · 0.99 · 1.00
```

- 多库常用区间（`0.6 ~ 0.8`）都在范围内，只是要多点几次 `+`；
- 单库的常规上限是 `0.033`，用 `0.01` 的刻度可以设 `0.01 / 0.02 / 0.03`；
- 需要 `1.0` 以上的阈值（多库筛「原文级命中」）只有命令行能做：

```bash
ki search "你们的查询" -s <视图名> --threshold 1.5
```

---

## 六、什么时候阈值不起作用

| 情况 | 为什么 |
|---|---|
| **全文模式**（`--mode fulltext`，或页面切「仅全文」） | 全文的分数是字面匹配分，几十到几百，与混合检索的量级完全不可比，套用阈值会一次清空 |
| **降级为全文**（embedding 不可用、超时） | 同上，系统自动跳过阈值判断，并在页面上标注「本次为关键词降级检索，Threshold 不生效」 |
| 向量库被占用 / 维度不匹配导致全部库被跳过 | 没有结果可比，看的是「跳过了哪些库」的提示，不是阈值 |

---

## 七、结果为空怎么排查

按这个顺序看：

1. **阈值是不是大于当前模式的分数上限？**
   —— 单库超过 `0.033`、多库超过 `1.0` 时，大概率是阈值太高。先把阈值拖回 `0`。
2. **有没有提示「已跳过的库」？**
   —— 视图里的某个成员库没有向量索引、或维度与配置不一致时会被跳过，这是漏召回的主因，与阈值无关。
3. **有没有「已降级为全文检索」的提示？**
   —— 降级后阈值不生效，若仍是空结果，说明关键词也没命中，换词或换 `--mode fulltext`。
4. **`limit` 是不是被自己设小了？**
   —— 过滤后剩余条数不足时不会补位。

---

## 八、两个常见误解

**① 「0.8 是不是等于 80% 相关？」**
不是。它不是相似度百分比，只是「相似度 + 字面加成」算出来的一个分数。只有**同一模式内**互相比较才有意义。

**② 「阈值设高一点，结果会更准」**
不成立。阈值只做减法：它不会让不相关的结果变相关，只会让结果变少。**排序质量由排序规则决定，阈值只负责砍掉尾巴。**
