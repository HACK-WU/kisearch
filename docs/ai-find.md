# AI 查找：给事件挑参考文档

「AI 查找」用在**事件详情页**：围绕一件正在处理的事，从知识库里找出值得作为参考的文档，你勾选后它们成为这个事件的参考文档，之后 AI 分析、对话都能读到。

它不是搜索框，是**候选清单**——最终加不加由你决定。

## 怎么用

1. 打开事件详情 → 点「AI 查找」。
2. 等它出候选（只读，不改任何文档）。
3. 看理由和分数，把真正相关的勾上（分数够高的默认已勾）。
4. 点「加入」→ 详情页的参考文档列表里出现这些文档。

弹窗里的候选已经排除了「已作为关联文档」和「已经在参考文档里」的，不会重复出现。

## 检索范围：查哪几个库

默认**只查当前事件所在的库**。要跨库查，到「AI 设置 → AI 查找 → 检索范围」加额外库：

- 当前事件所在库**恒定参与**，不用配；
- 额外库最多 5 个，可以选库，也可以选**知识视图**（视图会按其成员库一起查）；
- 选择器里只出现你有权访问的库；视图要求**它的全部成员你都已授权**；
- 改完保存立即生效，不用重启。

保存时如果名字不存在、或视图没有成员，会直接拒绝并告诉你是哪一项——不会存下一个永远不会生效的配置。

查找时如果某个库因为权限或已被删除而不可用，它会被**跳过**，弹窗顶部会写明跳过了谁、为什么；其余库照常出结果。

## 候选怎么看

| 看到什么 | 含义 |
|---|---|
| 文档名 + group 路径 | 候选本身；跨库查找时前面会带**所在库名** |
| 分数（如 `0.82`） | 同一批候选里的相对高低，**不同库之间不能直接比** |
| `库内 #1` | 这篇在它自己库里排第一（跨库比较时这个更可靠） |
| `N 处命中` | 正文里有 N 个片段命中，不是 N 篇文档 |
| 理由 | 命中了哪些关键词、是否与关联文档同组 |
| 可见性标记 | 这篇文档当前对检索是否可见 |

跨库查找时结论要按「库内排名 + 理由」判断，不要拿两个库的分数横向比——不同的库分数不在同一把尺子上。

## 加入之后要注意什么

- **同一篇不能既当关联文档又当参考文档**，会直接拒绝。
- 目标文档如果**被一个已收口的事件锁在不可检索阶段**，加了也永远读不到，所以会拒绝（`REF_DOC_NOT_SEARCHABLE`）。
- 如果只是被**还没收口的事件**临时锁住，可以加进来，但要等那个事件走到可检索的阶段才能读——弹窗会提示是哪一件。
- 没有权限的库里的文档加不进来（`FIND_TARGET_NOT_AUTHORIZED`）；文档名或 group 写错、目标库里根本没这篇，也会被拒绝（`REF_DOC_NOT_FOUND`）。

## 参考文档后来失效了会怎样

引用不会被静默删掉，而是标成失效，并告诉你原因：

| 标记 | 原因 | 怎么办 |
|---|---|---|
| 文档已删除 | 被引用的文档本身没了 | 找到新的替代文档重新加入；确认不需要就删掉这条引用 |
| 源库不存在 | 文档所在的那个库已被删除，或你已无权访问 | 让管理员确认库的状态与授权 |

## 同时有多个人查找会怎样

- **不同事件**：可以同时查找，默认最多 3 个同时进行。
- **同一个事件**：后来的请求会**排队**等前一个结束（不会互相看到对方的结果）；最多 8 个排队，排队超过 20 秒会提示稍后再试。
- 排队期间关掉弹窗（或点停止）会立刻取消排队，不占位置。

## 出错怎么补救

| 现象 | 原因 | 补救 |
|---|---|---|
| 弹窗提示「不可用：XXX（不存在）」 | 检索范围里配了一个已经不存在的库或视图 | 到「AI 设置 → AI 查找 → 检索范围」删掉它再保存 |
| 提示「不可用：XXX（无权访问）」 | 该库/视图不在你的授权范围内 | 找管理员授权，或把它从范围里移除 |
| 提示「视图没有成员或成员已变更」 | 视图被清空或成员改过，导致你已不全有权限 | 让视图维护者补齐成员，或改配成员库 |
| 查找整体失败（`SEARCH_UNAVAILABLE`） | 所有目标库的检索都不可用（多见于向量侧异常） | 先确认单库检索是否正常；恢复后重试 |
| 提示「队列已满」 | 同一事件已有查找在跑，或全局并发的 3 个位置都被占用，且排队也满了 | 等前一个结束再试 |
| 提示「排队等待超时」 | 前一个查找跑了很久，排队超过 20 秒 | 等它结束后重试 |
| 提示「查找超时」 | 单次最长 45 秒仍未出结果 | 缩小检索范围、减少额外库，或改用 `ki_search` 自己检索 |
| 查找等一会儿就失败，**没有错误码** | 反向代理 / 网关先把这条长请求断开了（服务端日志会记一条「响应前断开」并带已耗时） | 在部署环境跑一次探针确认：`node scripts/probe-find-timeout.mjs --event <事件 id> --scope <库名>`，按它给出的建议放行网关长请求，或缩小检索范围 |
| 候选一条都没有，提示「库里没有可检索内容」 | 目标库本身没有已索引文档 | 先把文档导入/写入目标库 |
| 候选一条都没有，提示「没有命中」 | 事件里提不出有区分度的线索词，或确实没有相关文档 | 在事件标题/描述里补上错误码、接口名、组件名等具体信息后重试 |

## 深度查找为什么是「同步等」

深度查找是**一次请求等一个结果**，不是后台任务：
它的产物是一份一次性的候选清单，勾选完就没用了，做成后台任务反而要引入任务号、轮询、过期清理三套东西。

代价也很直接 —— 这条请求会一直占着连接，**反向代理/网关若在自己的超时点先断开，前端只会看到一个没有错误码的失败**。遇到这种情况先跑 `scripts/probe-find-timeout.mjs` 实测，再决定放行网关还是缩小检索范围。服务端日志里对应的一行是「响应前断开（用户取消或网关超时）」并带已耗时，可以据此判断是用户关掉还是网关掐断。

除此之外只剩一条内部的 **45 秒硬超时**防止请求无限挂住 —— 它**只影响单次查找**，不影响其它功能，也不能配置。轮次、候选数、每日可用次数都不设限（2026-11 起取消）。

## AI 调用工具的次数上限

「AI 设置 → AI 查找 → 工具调用上限」控制 AI 在**一次**查找里最多能调用几次工具（检索、读正文、看知识树、看标签合起来算）。

- **默认 15 次**，可填 2–30 的整数；**这一项没有「不限制」**，上限始终有效；
- 这个数字会**一起发给 AI**，让它先规划好顺序再动手，而不是把次数花在反复试探上；
- **别卡到最低**：AI 至少要一次检索加一次读正文，只够做这两件事时几乎选不出文档；
- 次数用满后，查找会立刻停下并把已读到的内容整理成结论 —— 候选可能偏少，面板会明说「工具调用次数已用满（N 次）」，这时调高上限或缩小检索范围再跑一次即可；
- 填错了（留空、小于 2 或大于 30）不会保存，输入框会提示范围并在离开时回退到当前生效值。

## 和其他 AI 配置的关系

「AI 设置」里的三项能力互相独立：

- **AI 对话**：聊天助手的提示词 / Skill / 工具；**源码只读目录与 AI 分析共用**（见下）；
- **AI 分析**：分析事件源码的目录、提示词、Skill、工具；
- **AI 查找**：本页。

三条能力的提示词 / Skill / 工具开关互相独立，改一项不会影响另外两项；**唯一的共享面是代码目录**：AI 设置 → AI 分析 →「代码目录（分析 / 对话共用）」同时决定分析与对话能读哪些代码。对话侧的源码只读工具（`fs_*`）默认开启——升级后若该目录已配置，对话会直接获得只读代码能力；不需要时到「AI 对话 → 工具与权限」关闭 `fs_*`。视图会话不单独配置目录，按成员库各自的映射读取。查找的 Skill 与工具只有**只读**的知识库查询能力，不会修改你的文档。

## 目前还没生效的部分

「AI 查找」**只有模型通道**（2026-11-18 起，确定性快速查找已下线）：模型多轮检索 + 读正文后给出候选，
因此同样的输入**不保证同一批结果**（模型判断有随机性），但每条候选都附「为什么相关」。

> **没有快速通道了**：不调模型的"查找"本质是关键词 + 向量检索，与用户点开"AI 查找"的预期不符；
> 想精确控制检索词时请用 `ki_search`。


设置页里的「基础提示词 / Skill / 思考级别」**现在全部生效**（因为只有模型通道）；「检索范围」决定事件库之外还要查哪些库。
