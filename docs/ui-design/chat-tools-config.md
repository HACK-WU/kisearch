## 2. 布局

### 2.1 P1 面板头部（唯一的结构改动）

```
┌──────────────────────────────────────────────┐
│ AI 对话   [◰ 会话名  6 ▾]        [⚙]        │  ← 默认态
└──────────────────────────────────────────────┘
       ↑ 既有                        ↑ 新增（唯一结构改动）
```

⚙ 放在最右、与会话 chip 同排，**不新增第二条折叠条**（既有走查结论：面板内再加折叠就不像聊天应用）。

### 2.2 P2 配置抽屉（**两级结构：列表 → 详情(预览/编辑)**）

> 2026-09-30 修正（用户反馈）：提示词与 skill 的**内容不直接摊开**——列表层只显示条目卡片
> （名称 + 一行摘要 + 状态），点开先看**预览**，再点「编辑」才进入编辑态；**skill 是列表**（可多条）。

```
列表层（默认）
┌────────────────────────────┐
│ 对话配置              [✕]  │
│ 作用域  [全局 ▾]           │
│         · 下一次提问生效    │
│ ── 提示词 ───────────────  │
│ ┌────────────────────────┐ │
│ │ ▤ 基础提示词           │ │
│ │   你是 kisearch 的…    │ │  ← 一行摘要（截断）
│ │   218 字 · 已修改   ▸  │ │
│ └────────────────────────┘ │
│ ── Skill ────────────────  │
│ ┌────────────────────────┐ │
│ │ ⚙ 知识库检索            │ │
│ │   先 ki_search 找片段…  │ │
│ │   486 字 · 默认     ▸  │ │
│ └────────────────────────┘ │
│ + 新增 skill               │  ← 虚线（数据模型待定，见待确认 10）
│ ── 工具与权限 ────────────  │
│ 只读 …（开关）              │
│ 写入·危险 …（开关+确认）     │
└────────────────────────────┘

详情层（点条目后）
┌ ‹ 返回   基础提示词 ────── ✕ ┐
│ [ 预览 | 编辑 ]   ← 分段切换  │
│ ──────────────────────────  │
│ 预览：只读正文 + 元信息        │
│   218 字 · 上次修改 09-30     │
│ 编辑：多行编辑区 + 字数校验     │
├───────────────────────────  │
│ [恢复默认]    [取消] [保存]   │
└─────────────────────────────┘
```

**两级保存口径**：详情层**自己保存**该条目（保存后回列表、卡片状态更新）；列表层底部保存栏负责**作用域 + 工具开关**。两条路径都用 toast 反馈，避免"改了不知道存没存"。

## 4. 视觉 token

**100% 复用 `ki.css`**（`--ki-*`），本方案不新增任何全局 token。面板级变量只声明 1 个：

| token | 值 | 用途 |
|---|---|---|
| `--ki-chat-cfg-knob` | `#fff` | 开关滑块（面板级声明，收敛本方案唯一硬编码色） |

> **2026-09-30 第四轮修正**：原表声明的 `--ki-chat-config-w: 420px`（抽屉宽度）**不成立** —— 常驻面板仅 `380px`（`ki.css:1745-1761`，区间 360~420），
> 抽屉比容器还宽；配置层实际是 **panel-scoped 全覆盖**（`position:absolute; inset:0`），故删除该 token。
> `--ki-chat-tool-max-h` / `--ki-chat-tool-indent` 未单独建 token：滚动上限直接写在 `.ki-chat-tool { max-height: 300px }`，
> 缩进复用时间线既有间距。**若要恢复为 token，需与实现一并改**。

**套用风格 skill 的准则（红线/适用项）**

| 准则 | 本方案落地 |
|---|---|
| 不重写、在既有栈上增量 | 只加 ⚙、抽屉、展开区；面板结构、消息流、来源交互全不动 |
| 数据用等宽/表格数字 | 耗时、命中数、行号、字节数一律 `font-variant-numeric: tabular-nums` |
| 字重不只有 400/700 | 层级用 400 / 500 / 600（标题 500、强调 600） |
| 必须有 focus ring | 所有可交互元素有可见聚焦环（无障碍硬要求） |
| 交互有过渡（150–300ms） | 抽屉 240ms、按钮态 160ms、开关 180ms；只用 `transform`/`opacity`/`background` |
| 按钮有按下反馈 | `transform: scale(.96)` |
| 不许有 loading / empty / error 缺口 | 保存中、保存失败、工具失败、空工具列表都有专门呈现 |
| 错误文案说人话、无感叹号、无 "Oops" | 「保存失败，请重试」/「文本不能为空」/「参数不是合法 JSON」 |
| 圆角分级 | 容器 16px（抽屉/卡片）、控件 8px（按钮/输入）、内层 6px（徽标） |
| 文案 sentence case | 中文同理：短句、直陈，不用「请点击此处」这类冗余 |

## 7. demo

`demo/chat-tools-config/index.html`（**单文件自包含**，128KB，双击即开）

> **为什么 `ki.css` 是内联而不是 `<link>`**（2026-09-30 修复）：
> 预览面板是把**单个 HTML** 从 `static-html/<hash>/` 路由下发的，相对路径 `../../web/src/styles/ki.css` **取不到** →
> 整页裸奔（已实测）。故把真实 `ki.css` **原样内联**进 `<style>`（无外部 `url()` 依赖，仅一处 data:URI 内联 SVG，安全）。
> **维护约定**：改样式请改源文件 `web/src/styles/ki.css`，再重新生成 demo 的内联块；demo 内联块不要单独改。

> **2026-09-30 第三轮修正**（用户反馈「提示词和 skill 内容不要直接显示出来，点开后先预览再编辑；skill 是列表」）：
> 配置层从「两个大 textarea 直接摊内容」改为**两级结构**：列表层只显示条目卡片（名称 + 一行摘要 + 字数/状态），

> Skill 为**列表**（可新增/删除；内置条目只可"恢复默认"不可删除）；新增条目的数据模型（命名/触发引用/作用域归属）**待确认**（报告 §5-10）。

> **2026-09-30 第四轮修正**（PM 走查 M4：真机截图 + 计算样式实测发现 14 条，本轮修 12 条）：
>
> **渲染/交互缺陷（已修）**
> 1. **配置入口被压成「配/置」竖排**（实测盒 `46×26`、图标被压到 `11×11`）→ `flex: 0 0 auto; white-space: nowrap` + `svg 14×14`（现 `60×26`）。
> 2. **配置层横向溢出 113px**（`bodyScrollW 477 / clientW 364`）→ 根因是 grid 项 `min-width:auto` 被摘要长文本撑开；
>    改 `grid-template-columns: minmax(0,1fr)` + 卡片 `min-width:0`（现溢出 0）。
