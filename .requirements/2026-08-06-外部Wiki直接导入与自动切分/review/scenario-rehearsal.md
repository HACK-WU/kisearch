## 1. 全局理解声明 + 角色清单

### 全局理解
- **业务目标**：外部 Wiki 无 AI 依赖直导入库 + 大文档自动切分 + 增量 git diff 直连
- **系统位置**：上游 外部 Markdown 目录（git 仓库）→ `scan-kb import` → 下游 向量库 + KB JSON → 检索/查询
- **整体成功判据**：REQ-01~15 验收标准；数据一致性（文件↔chunk 映射不丢、无孤儿向量）；性能（数千文件可接受）；兼容（旧数据可读、MCP 工具名不变）

## 3. 场景推演详情

### 场景 1：全量直导
- **数据走向**：5 项通过 / 0 存疑 / 0 失败
- **设计点**：D-1（文件→N chunk→N memoryId）✅、D-7（content 纯化）✅、D-4/D-5（参数持久化+sourceDir）✅
- **全局回扣**：✅ 成立（无 AI 依赖、原文入库、sourceDir 写入达成）

### 场景 2：增量直连（协作）
- **数据走向**：5 项通过
- **设计点**：D-2（多值 Map 定位）✅、D-3（全 chunk 覆盖）✅、写序修复 ✅
- **意外场景**：chunk 数量变化（3→4）先写新后删旧最终一致 ✅；写入中断旧保留下次收敛 ✅；文件重命名 R→deleted+added 全量重建 ✅
- **全局回扣**：✅ 成立

### 场景 3：检索与原文定位
- **设计点**：REQ-09（无 isFullText）✅、REQ-05（无词云）✅、P-2（chunk 定位，仅 chunk 非整篇）🟡 已接受
- **全局回扣**：✅ 成立

### 场景 4：异常与边界
- 无 git 跑增量 ⚠️（需求未定二选一）
- 超大文件 10MB ⚠️（P-7 待定）
- 全量重导改 chunk-size ⚠️（D-8 "首次"定义模糊）
- 并发导入同 scope ✅
- 空目录导入 ⚠️（需求未定义）

## 4. 问题汇总

| # | 类型 | 角色 | 场景 | 问题描述 | 功能影响（预期 → 实际） | 建议 | 严重度 |

| 1 | 需求一致性 | CLI用户 | 无 git | §4.4"降级全量**或**报错"未定二选一 | 预期：增量行为明确 → 实际：实现者自行二选一，可能不符合用户期望 | 明确为"无 git 时报错（提示先 git init）"或"降级全量（警告）" | 🟡 |

| 3 | 设计点模糊 | CLI用户 | 参数变更 | D-8 与命令行 `--chunk-size` 优先级在重导时未定 | 同上 | 结合 #2 一并明确 | 🟡 |
| 4 | 边界覆盖 | CLI用户 | 超大文件 | P-7 待定 | 预期：超大文件可控 → 实际：10MB→10000 chunk 向量爆炸 | 技术设计阶段定 MAX 上限（如 2MB）+ 超限告警 | 🟡 |
