# SR-01 不做什么（越界了怎么办）

> 本文件是**边界硬约束**。窗口做超出范围的事 = 越界，拼接期会被拒收门拦下并退回。

## 1. 本片不做

| 不做 | 归属 / 原因 |
|------|-----------|
| **前端任何改动** | SR-02 独占（`web/**`） |
| **图片输入能力**（API-09/10、多模态消息体） | **T13 拍板后置 V2**；本期契约保留但不实现 |
| **检索以外的工具**（写入 / 删除 / 导入类） | S07 §8 明确排除 |
| **多步自主规划 Agent**（任务分解、规划循环） | 只做「检索 → 作答」，R21 已限轮次 |
| **跨 scope 检索** | N23 禁止；scope 由 daemon 注入，工具 schema 无 scope 参数 |
| **纯向量检索模式**（`mode=semantic`） | T9 拍板取 `hybrid`，零改动复用 |
| **重排 / 查询改写** | S07 §8 排除 |
| **修改 `src/search.ts`** | R18：必须复用，不新建检索链路 |
| **修改 `.delivery/mocks/`** | 脚手架，由切片阶段统一产出 |
| **修改契约**（`chat-contract.ts` / 前端副本 / 骨架） | 只有批次边界 + 回 `design-craft` 才能改 |
| **改片级验收测试的断言** | 改断言 = 自己出题自己答 |

## 2. 越界了怎么办

| 情况 | 处理 |
|------|------|
| 发现必须改 `src/search.ts` | **停下写阻塞** —— 意味着 R18「复用」前提不成立，属设计问题 |
| 发现必须改 `web/**` | 写阻塞（那是 SR-02 独占区，即便只加一个类型） |
| 发现需要新 mock 场景 | 写阻塞（mock 属脚手架） |
| 发现契约有缺口（缺字段 / 语义不明） | 写阻塞 → 批次边界回 `design-craft` 修订（**不得就地改**） |
| 发现与 SR-02 必须共享可变逻辑 | **停下报用户** —— 这是**划分修订信号**（L2），代价比契约修订大一个量级 |
| 实现中觉得某条验收标准写错了 | 写阻塞上报（**不自行改断言**） |

## 3. 三条最容易"好心办坏事"的动作（禁止）

```text
❌ 为了让测试变绿而改断言          → 掩盖真实缺口，验收效力归零
❌ 顺手改契约"让它更好用"          → 契约漂移，其他片全部作废
❌ 顺手改一下 web/ 的前端文件       → 越界，必然与 SR-02 冲突
```

> 三个动作都比原问题造成更大的损害。**遇到任何一个，写阻塞，等批次边界。**
