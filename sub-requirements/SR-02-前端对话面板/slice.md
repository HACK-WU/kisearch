## 1. 目标

在 Web 任意页面右侧提供**常驻可收起的 AI 对话面板**：多轮问答、流式输出与生成中状态、来源引用可点击回原文、历史会话管理，且**关闭面板不丢内容、不中止生成**。

## 2. 场景

1. **任意页面问答**：在 `/browse` 或 `/search` 打开面板提问 → 看到「正在检索知识库…」→ 流式出字 → 回答附「引用 N 处」→ 点击来源打开原文并高亮
2. **切页面不丢**：生成中途切到别的页面 → 面板内容与生成**继续**（AppShell 级常驻）
3. **关闭不中止（D15）**：生成中点顶部开关关闭面板 → 生成**继续**；重开能看到完整内容与思考块
4. **降级可见（N17）**：模型不支持工具调用 → 气泡上标注「本次未使用工具检索」，不得静默
5. **隐私确认（T12）**：首次使用弹一次性确认；未确认前**阻塞发送**

## 5. 划分理由（写进包，不留在对话里）

| 项 | 内容 |
|----|------|
| **为什么这样切** | 前端是**逐层依赖的串行链**（`AppShell`(常驻 store) → `ChatPanel`(事件消费) → 来源 UI / 工具步骤），**内部无法并行**，故整体为一片 |
| **为什么与 SR-01 可分** | 目录天然互斥（`web/src/**` ∩ `src/lib/**` = ∅），接口即 **SSE 事件协议 + config 字段**（骨架已冻结形状）→ 用 mock 即可独立开工 |
| **与谁不可并行及原因** | 前端内部各层共享**同一份常驻状态**（`chatStore`），拆开会让两片都要改同一个 store → 互斥不成立 |
| **否决过的划分方式** | ① **按组件拆**（面板 / 来源 UI / 工具步骤各一片）→ 否决：三者共享 `chatStore` 状态形状，拆开必冲突；② **前端只做"壳"、SSE 消费留给 SR-01** → 否决：跨技术栈，属越界 |

## 6. 计划内的阻塞点

| 阻塞点 | 处理 |
|--------|------|
| **DOM 测试环境缺失** | 项目 `web/test` 只有 node 测试。第 5/6 项验收需人工或自建 DOM 基建 —— **实现时决策并如实标注** |
| **`RevealStream` 用法** | SSE 用 `fetch` + `ReadableStream`（**不用 `EventSource`**：只支持 GET、无法带请求体、无法中途 abort） |
| **关闭面板不卸载** | 状态必须全在 `AppShell` 级 store；组件内不得持有流式累积态（D15 硬约束） |
| **窄屏降级** | 前置门②（真实布局基线）**未清** —— 本窗口保守实现：面板宽度 360–420px，窄屏降级阈值先取 1400px，并在返回时标注「阈值待基线补测后校准」 |
