# SR-02 不做什么（越界了怎么办）

## 1. 本片不做

| 不做 | 归属 / 原因 |
|------|-----------|
| **后端任何改动**（`src/**`） | SR-01 独占 |
| **图片输入 UI**（上传 / 粘贴 / 引用 KB 图） | **T13 后置 V2** |
| **新建高亮机制** | 复用既有 `ModuleDrawer` + `MarkdownPreview`（R20 明确要求复用） |
| **修改 `web/src/components/**` 既有组件** | 跨需求影响（5 个页面在用）；需要改 → 报阻塞 |
| **重写 `AppShell` 布局** | 只改预留的挂载位 |
| **改契约形状**（`chatContract.ts` 字段） | 契约修订须走批次边界 |
| **改片级验收测试的断言** | 改断言 = 自己出题自己答 |
| **移动端专项适配** | S03 §8 明确排除（窄屏仅保证可用的浮层形态） |
| **虚拟滚动**（消息 >500 条） | S03 §8 排除（仅提示新建会话） |

## 2. 越界了怎么办

| 情况 | 处理 |
|------|------|
| 事件缺字段 / 语义不明 | **写阻塞** → 批次边界回 `design-craft`（不许前端自行补字段） |
| 需要改 `src/**` | 写阻塞（SR-01 独占区） |
| 发现 `chatContract.ts` 与后端形状不一致 | **写阻塞**（契约漂移，不得自行"对齐"） |
| 想让来源引用更好看而改 `ModuleDrawer.tsx` | 写阻塞（既有组件，动它影响 5 个页面） |
| 觉得某条验收标准写错 | 写阻塞（不自行改断言） |

## 3. 三条最容易"好心办坏事"的动作（禁止）

```text
❌ 把流式状态放在 ChatPanel 组件内 → 关闭面板即丢内容（直接违反 D15）
❌ 用 EventSource → 无法 POST、无法 abort（与契约的 fetch+ReadableStream 冲突）
❌ 为了"跑通"而在前端硬编码事件字段 → 掩盖后端契约缺口，拼接期必炸
```

## 4. 已知未清前置门（本窗口的应对）

**前置门②（真实页面布局基线 1280/1440/1600）未清** → 窄屏降级阈值先取 **1400px（初值）**，
实现后在返回中标注「**阈值待基线补测后校准**」，**不得声称已达成 R3 的窄屏降级验收**。
