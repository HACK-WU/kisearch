模块采用「主线程门面 + 单例 worker 进程」的双层架构：
- `engine.ts` 暴露 `ZvecEngine` 类，作为唯一对外 API 入口（`create`/`open`/`tryOpen`/`probe`），封装配置校验、Embedding 批处理（按 EMBED_BATCH_SIZE=64 切分并去重）、Filter 编译、路由（调用 `search/router`）以及结果归一化（`search/normalize`）。
- `proxy.ts` 的 `ZvecEngineProxy` 负责用 `node:worker_threads.Worker` 启动 `worker.js`，维护状态机（init→opening→open→closing→closed/crashed/failed），通过带 UUID id 的请求/响应协议与 worker 异步通信，并在 crash/exit 时拒绝所有 pending Promise。
- `worker.ts` 是独立加载的 worker 入口，持有全局 `ZVecCollection` 句柄，以串行消息循环（`port.on('message' → dispatch → handleXxx`）执行所有 zvec 同步 API（`upsertSync`/`insertSync`/`updateSync`/`querySync`/`multiQuerySync` 等），写入分批并通过 `setImmediate` 让出事件循环给查询插队。
- `worker-protocol.ts` 定义跨进程消息契约（`WorkerRequest`/`WorkerResponse`/各类 Payload），使用 `Float32Array` + transfer list 实现零拷贝向量传输，并通过 `serializeError`/`deserializeError` + `ERROR_CONSTRUCTORS` 映射在进程间重建类型化异常。
- `types.ts` 集中声明公共类型（配置、文档、Filter、检索请求、WriteResult、Hit、ProbeResult 等），`errors.ts` 定义继承自 `ZvecEngineError` 的 11 种核心异常及内部异常，仅 index.ts 导出的 11 种核心异常构成对外契约。
- 依赖方向单向：engine → proxy → worker；engine 依赖 `schema/validator`、`filter/compiler`、`search/router`、`search/normalize`、`embedding/provider`，但 worker 不反向引用 engine。
