模块采用「主线程门面 + dedicated worker_threads」的隔离架构：engine.ts 作为唯一入口，通过 proxy.ts 启动并复用 worker 进程来持有 zvec 原生集合句柄，避免在 Node 主线程直接调用 C++ 扩展导致的阻塞与锁竞争。
- 配置与模式：schema/builder.ts 与 schema/validator.ts 负责创建/打开时的 Schema 构建与校验；filter/compiler.ts 将 Filter DSL 编译为 SQL 片段供 worker 执行。
- 数据流：写入路径（upsert/insert/update/delete）先按是否需 embed 拆分文档，经 embedding/provider.ts 抽象接口（siliconflow.ts 实现）批量嵌入后转为 Float32Array，再经 proxy.send('upsert'|'insert'|'update'|'delete') 下发到 worker；检索路径由 search/router.ts 根据请求类型路由到 query/multiQuery，必要时触发 embed，再由 search/normalize.ts 把 RawHitPayload 归一化为 Hit[]。
- 错误与协议：errors.ts 集中定义 v5 §4.5 契约的 11 种核心异常；worker-protocol.ts 定义主/从进程间消息载荷；index.ts 仅导出 ZvecEngine、类型、SiliconFlowProvider 与异常，Worker/Embedding 系列标记 @internal 不暴露。
- 生命周期：create/open 静态工厂构造 proxy → spawn 对应操作 → 返回实例；probe 通过临时 proxy 加超时探测集合是否存在/被锁/健康；destroy/close 保证原生 closeSync 释放 LOCK 与 RocksDB 句柄。
