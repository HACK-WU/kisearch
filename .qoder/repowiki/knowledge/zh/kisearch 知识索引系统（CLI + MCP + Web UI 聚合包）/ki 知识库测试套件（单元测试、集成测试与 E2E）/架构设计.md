测试按职责分层组织：
- `test/*.test.ts` 与 `test/*.test.mjs` 为基于 `node:test` 的单元测试，直接 import 源码模块（如 `../src/lib/mcp-http.js`、`../dist/zvec-engine/index.js`），通过构造临时 scope、临时目录和 mock embedding 进行隔离验证。
- `test/e2e/*.mjs` 为网络/外部依赖驱动的端到端测试，通过 `execFileSync('npx', ['jiti', 'src/xxx.ts', ...])` 启动真实脚本子进程，使用 `getTestEnv()` 注入 `KI_CONFIG_PATH` 指向临时配置。
- `tests/e2e/` 存放人类可执行的 journey 记录、计划与报告（Markdown），作为手工验收文档而非自动化用例。
- `test/fixtures/mock-wiki/` 提供预置的 git Wiki 仓库，供 scan-kb 增量/全量导入场景复用。
- `test/test-config.ts` 是共享基础设施：在进程启动时创建 `/tmp/ki-test-*` 临时配置文件，设置 `vectorDir`/`backupDir` 到隔离目录，并通过 `registerTestScope` 动态注册 scope；`getTestEnv()` 剥离 IDE 注入的 `NODE_OPTIONS` 与 `CODEBUDDY_SAFE_DELETE_*`，避免子进程被安全删除拦截挂起。
- `test/zvec-lock-demo/` 是 zvec 引擎 WAL/锁复现用的演示数据与 worker 脚本，独立于主测试运行。
依赖方向单向：测试 → 源码 (`src/`) / 编译产物 (`dist/`)，不反向依赖生产代码。
