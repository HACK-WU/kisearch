本模块由三个相互独立的子目录组成，共同构成对知识索引器的 E2E 验证与向量引擎探测层：
- `.e2e-run/`：通过 `env.sh` 注入 Node v22、SILICONFLOW_API_KEY 与 `KI_CFG`（指向 `ki-config.yaml`），以隔离的 `kb/`、`backup/`、`vector/` 目录作为数据平面；`mcp-comprehensive-test.mjs` 作为 MCP HTTP 客户端，按 initialize → tools/list → tools/call 流程对本地 `http://127.0.0.1:7423/mcp` 执行基本功能、性能、并发、压力四类测试并输出统计；`repro-hang*.mjs`、`repro-vc.ts`、`verify-auth-log.ts` 用于复现并发竞态挂起与认证日志问题；`manifest.json` 是 BKMonitorWiki 知识库的元数据清单，配合 `src-monitor/` 下的中文架构文档作为被测数据源。
- `zvec-probe/`：Python 侧探针，`gen_bulk.py` 从 `/root/bk-monitor/ai-docs/**/*.md` 批量抽取文档生成 `.bulk*.json` 测试集，`compare.py`、`memcmp-config.yaml`、`zvec_demo.py` 驱动 alibaba/zvec 的 HNSW + FTS(jieba) + 标量过滤混合检索，并通过 Lancedb 事务文件持久化中间结果，用于与 Node 版对齐验证。
- `zvec-probe-node/`：Node 侧探针，依赖 `@zvec/zvec` v0.5.0，`zvec_demo.mjs` 用词哈希 bag-of-words 构造稠密向量，演示创建集合、插入、optimize、RRF 融合、原生 multiQuerySync(rerank:'rrf')、标量过滤与关闭重开持久化全流程；`probe_h04.mjs`、`verify_blocking.mjs` 针对阻塞场景进行专项验证；`mcp_live_kb/` 为 RocksDB 格式的实时向量库快照。
依赖方向单向：两个探针均只依赖底层 `@zvec/zvec` / alibaba/zvec 引擎，不反向依赖主工程业务代码；`.e2e-run` 中的脚本通过 HTTP 调用已启动的主服务 MCP 接口，形成“外部测试器 → 主服务”的单向边界。
