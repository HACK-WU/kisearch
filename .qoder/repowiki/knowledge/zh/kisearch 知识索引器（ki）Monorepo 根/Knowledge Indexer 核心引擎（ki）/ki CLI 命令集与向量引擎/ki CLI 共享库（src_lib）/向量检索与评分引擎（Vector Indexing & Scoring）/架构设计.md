模块以 `vector-client.ts` 为核心适配器，对外暴露 `vectorSearch/vectorStore/vectorBulkStore/vectorDelete` 等统一接口，内部通过进程内单例 `ZvecEngine`（来自 `dist/zvec-engine/index.js`）管理集合 `kisearch`，字段约定为 dense/content/tag/scope/group；通过 `serializeEngineOp` 串行化 probe/create/open/close 避免原生竞态，配合 `probeWithRetry` 撞锁重试、`enableIdleClose` 空闲释放锁以及 `withOpenTimeout` 超时保护，使多 MCP 实例与 CLI 短命令能共享同一向量库。

`batch-vectorize.ts` 在上层封装批量向量化：`bulkVectorize` 按 200 条分批调用 `vectorBulkStore`，`batchVectorize` 串行逐条调用 `vectorizeOne`，二者均返回 path→docId 映射及错误明细；`deleteMemory` 走 `vectorDelete` 用于增量修改。

`rebuild-vector.ts` 面向 restore 后场景，从已还原 KB 的 `index.json` 和 `relations-cache.json` 收集三类条目（ki-search 内容、ki-relation 关系、ki-path 路径），清空旧向量后批量写入，并通过 `updateMemoryIds` 将 docId 回写 cache 的 memoryId/memoryIds 字段。

`scoring.ts` 独立于向量层，提供纯函数式评分：`calculateScore` 基于 useCount 与 lastUsedTime 的半衰期衰减，`recordUse` 带 5 分钟防刷与上限截断，`hybridPartition`/`partitionByScore` 实现新兴热区保留 + 历史热门填充 + 温冷分区 + 上限截断，`boundaryDecay` 处理新项进入热区时的边界分数衰减。

依赖方向：`batch-vectorize` → `vector-client`；`rebuild-vector` → `vector-client` + `path-vectorize`；`scoring` 仅依赖 `constants`，无外部 IO，可被上层任意消费。
