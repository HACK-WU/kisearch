本模块由两类构件组成：
- `scripts/` 下的可执行脚本，按职责分层：构建侧车（`build_sidecar.py` 调用 PyInstaller 将 FastAPI sidecar 冻结为单文件二进制并拷贝到 `apps/desktop/src-tauri/binaries/`，文件名带 rustc host triple）；安装冒烟（`desktop_install_smoke.py` 自动识别 .deb/.AppImage/.dmg/.app.tar.gz/.msi/.exe 并安装或解压出可执行路径，通过 `GITHUB_OUTPUT` 回传给 workflow）；API 冒烟（`desktop_api_smoke.py` 启动已安装桌面应用，轮询 `/api/v1/healthz` 后依次跑 dense/sparse 集合的创建、写入、浏览、搜索流程）；统一测试入口（`test_all.sh` 顺序执行 backend pytest、frontend vitest、desktop cargo test）；质量报告（`quality_report.sh` 汇总各层测试数/覆盖率/类型检查并输出 JSON）；预发布校验（`pre_release.sh` 串联上述所有门禁并产出 `artifacts/pre-release-result.json`）；开发用数据注入（`seed_demo.py` 向本地后端插入 demo collection）。
- `.github/workflows/` 下的 CI 与 Release 流水线：`ci.yml` 在 push/PR 到 main 时并行运行 backend（多 Python 版本 + 多平台矩阵）、desktop（Rust clippy/format/test）、frontend（pnpm lint/typecheck/unit）、E2E（Playwright）、安全审计（pip-audit/pnpm audit/cargo audit）、桌面构建与安装冒烟、DCO 签名检查；`release.yml` 在 `v*` tag 推送时触发四平台（macOS ARM64、Linux x86_64/arm64、Windows x64）bundle 任务，构建 sidecar → Tauri 包 → 安装冒烟 → 收集产物，最后合并产物创建 GitHub Release 并通过 twine 发布 PyPI。
依赖方向单向：workflow 调用 scripts，scripts 仅依赖各自语言的标准库与第三方工具（PyInstaller、rustc、hdiutil、dpkg、msiexec），不反向引用仓库源码逻辑。
