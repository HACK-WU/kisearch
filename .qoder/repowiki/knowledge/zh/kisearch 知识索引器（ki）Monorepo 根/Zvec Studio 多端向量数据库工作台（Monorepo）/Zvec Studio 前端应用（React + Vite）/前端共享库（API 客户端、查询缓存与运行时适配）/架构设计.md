模块按职责拆分为若干独立文件，形成清晰的依赖方向：
- `runtime.ts` 位于最底层，仅通过检测 `window.__TAURI_INTERNALS__` / `__TAURI__` 判断是否运行在 Tauri 桌面壳中，并暴露 `isTauri()`、`invokeTauri()`、`getSidecarStatus()`，不依赖任何上层模块。
- `api-client.ts` 基于 `fetch` 封装 HTTP 请求，自动处理 JSON 编解码、RFC 7807 Problem Details 解析、`x-trace-id` 透传，并通过 `resolveApiBaseUrl()` 在 Web (`/api/v1`) 与 Tauri (侧车 URL) 之间切换基地址；导出 `ApiClient` 接口与 `createApiClient` 工厂。
- `error-mapper.ts` 将后端 Problem Details、网络异常、任意 Error 统一映射为带 `code`/`messageKey`/`severity`/`traceId` 的 `UserFacingError`，供 API 层与 UI Toast 消费。
- `query-client.ts` 集中创建 `QueryClient`，配置重试策略（4xx 不重试、5xx 重试一次）、30s staleTime、全局 `onError` 钩子，供 TanStack Query 使用。
- `fs-api.ts` 基于 `ApiClient` 构建 `/fs/list`、`/fs/reveal` 的文件浏览能力，类型内联声明以解耦 OpenAPI 生成流程。
- `directory-picker.ts` 调用 Tauri 原生目录选择器，非 Tauri 环境返回 `unsupported`，由上层 UI 回退到浏览器端目录选择对话框。
- React 集成层 `api-client-context.ts` + `api-client-provider.tsx` 将 `ApiClient` 注入 React Context，供组件通过 Hook 获取。
依赖方向单向向下：React Provider → api-client → error-mapper/runtime；fs-api/directory-picker 依赖 runtime 或 api-client，彼此无循环依赖。
