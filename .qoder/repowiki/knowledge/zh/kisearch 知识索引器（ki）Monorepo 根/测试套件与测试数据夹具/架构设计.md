模块按职责划分为三层：
- `test/` 下为基于 Node.js `node:test` 的测试文件，按功能域命名（如 `cli-help.test.ts`、`mcp-http.test.ts`、`zvec-engine-search.test.mjs`），并通过 `test/test-config.ts` 在进程启动时创建隔离的临时配置文件（`KI_CONFIG_PATH` 指向 `/tmp/ki-test-*`），统一注入 `vectorDir`、`backupDir` 到临时目录，避免污染用户环境；通过 `registerTestScope()` 动态注册 scope，`getTestEnv()` 剥离 IDE 注入的 `NODE_OPTIONS` 防止子进程挂起。
- `test/e2e/` 存放端到端网络测试（`.network.mjs` 后缀），通过 `execFileSync('npx', ...)` 直接调用 `src/scan-kb.ts`、`src/kisearch-cli.ts` 等 CLI 入口，配合 `test/fixtures/mock-wiki/` 中的 git 仓库作为模拟外部 wiki，验证全量直导、增量导入、备份还原等完整链路。
- `test/zvec-engine-*` 系列测试共享 `zvec-engine-fixtures.mjs` 提供的 `mockEmbedding`、`makeConfig`、`hashVector`、`makeDbPath` 等夹具，使用内存/临时目录隔离每个用例的向量库。
- `test_data/` 提供大型真实知识库快照（`bk-monitor-wiki/`）、预生成的 group-index/relations-cache、snapshot tar 包、Python 脚本与 skill 配置，用于回归与性能测试。
- `.e2e-run/` 是独立于 CI 的本地 e2e 运行环境，包含 `env.sh`（设置 Node 版本、SILICONFLOW_API_KEY、KI_CFG）、YAML 版 `ki-config.yaml`、以及 `repro-hang*.mjs`、`verify-auth-log.ts` 等问题复现脚本。
依赖方向单向：测试 → 被测 CLI/模块 → 文件系统/向量引擎；测试之间通过共享夹具解耦，不互相 import。
