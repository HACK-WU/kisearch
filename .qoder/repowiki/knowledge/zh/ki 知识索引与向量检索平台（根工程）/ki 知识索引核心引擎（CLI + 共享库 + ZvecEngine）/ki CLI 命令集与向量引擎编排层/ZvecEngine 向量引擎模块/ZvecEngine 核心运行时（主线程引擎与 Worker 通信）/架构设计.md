模块以 `engine.ts` 中的 `ZvecEngine` 为对外唯一入口，通过静态工厂 `create/open/tryOpen/probe` 完成配置校验、路径预检与生命周期探测；内部维护 `schema`、`allowedFields`、`routerCtx` 等状态，所有 I/O 经 `proxy.ts` 的 `ZvecEngineProxy` 转发至 `worker.ts` 子进程，形成「主线程编排 + Worker 执行」的双层架构。

- 消息协议：`worker-protocol.ts` 统一定义 `WorkerRequest`/`WorkerResponse` 联合类型、各请求 payload（`WritePayload`/`QueryPayload`/`MultiQueryPayload` 等）、错误序列化 `SerializedError` 以及 `collectTransferables` 零拷贝传输 Float32Array。
- 进程通信：`proxy.ts` 用 `node:worker_threads.Worker` 启动 worker，基于 UUID 请求 id 关联 Promise，维护 `pending` Map、`state` 机（init→opening→open→closing→closed/crashed/failed），并实现 drain/close/terminate 有序关闭。
- 错误体系：`errors.ts` 定义继承自 `ZvecEngineError` 的类型化异常族，并通过 `ERROR_CONSTRUCTORS` 映射表在跨线程反序列化时重建精确异常类型。
- 依赖方向：`index.ts` 仅导出公共 API 与 11 种契约异常；`engine.ts` 依赖 `proxy`、`types`、`errors`、`search/router`、`filter/compiler`、`schema/validator`、`embedding/provider`；`proxy.ts` 仅依赖 `worker-protocol` 与 `errors`；`worker-protocol.ts` 反向依赖 `errors` 与 `types`，构成单向依赖环。
- 嵌入流程：`writeDocs` 按是否需 embed 拆分文档，按 `EMBED_BATCH_SIZE=64` 分批调用 `EmbeddingProvider`，批内去重文本避免重复 HTTP 调用，失败项记录进 `errors[]` 不影响成功项写入。
