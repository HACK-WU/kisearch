本模块由三个相互独立的 Node 可执行脚本组成（backup.ts / restore.ts / export.ts），每个文件均以 `#!/usr/bin/env node` 开头并通过 `process.argv.slice(2)` 自行解析参数，不依赖上层路由或框架。
- 依赖方向单向指向 lib/*：config.js（loadConfig/getScopeDataDir/getBackupDir）、scope.js（validateScope/路径构造）、backup.js（snapshot/listBackups）、preflight.js（checkWritable/checkDiskSpace/PreflightError）、vector-client.js（closeEngine 释放 worker/LOCK）、rebuild-vector.js（向量重建）、markdown-gen.js（Markdown 生成）、cli-args.js（未知 flag 检测与错误载荷）。
- backup.ts：校验 scope → 检查 relations-cache.json 确认已初始化 → 调用 backupScopeSnapshot 生成 snapshot.<ts>.tar.gz 到 config.backupDir/<scope>/snapshots，或 --list 列出已有备份。
- restore.ts：最复杂，支持三种模式——无参/--list 列出可用备份；--from-snapshot [--timestamp] [--yes] 从 tar.gz 覆盖还原（先 ensureTarAvailable + 预检父目录可写性与磁盘空间，再创建安全网快照、删除旧目录后 execFileSync('tar', ...) 解压，失败时自动回滚至安全网快照）；--rebuild-vector 单独重建向量并在成功后清除中断标记；最终统一输出 JSON 并通过 finally closeEngine() 释放资源。
- export.ts：仅读本地数据（group-index.json + relations-cache.json + local KB index.json），按 Group 树递归遍历 hot_relations，调用 generateMarkdown 写出 .md 文件，支持 --group 子树导出与 --yes 防覆盖保护。
三文件互不引用，各自维护独立的帮助文本与参数解析逻辑。
