src/lib 以单一职责文件组织，按职责划分为 scope_config_cli（scope/group-index.json）、data_store_wal（Store/WAL/导入写回）、vector_indexing（ZvecEngine 封装与冷热评分）、ai_markdown_progress（条目结构/frontmatter/进度）、health_version_guards（preflight/version-guard/interrupt/health-check）以及 mcp-tools（HTTP/stdio 传输与工具注册）六大子模块，并通过顶层共享文件横向串联：
- config.ts 集中加载 ~/.ki/config.yaml/json，提供 KiConfig 类型、默认路径、embedding/vectorDir/scopeMode/mcp.http 解析，被 scope.ts、store.ts、vector-client.ts、mcp-http.ts 等所有子模块通过 loadConfig() 读取。
- constants.ts 暴露 SERVICE_NAME、DEFAULT_PARTITION_CONFIG、DEFAULT_TAGS、KI_ROOT 等全局常量，确保 MCP healthz 探活、向量分区策略、模板目录在各子模块间一致。
- scope.ts 定义 GroupIndex/GroupIndexSource 类型并实现 validateScope/getKbDir/getGroupIndexPath，是 data_store_wal、vector_indexing、mcp-tools 共同消费的唯一 scope 入口。
- 数据流自下而上：config → scope → store/wal → vector_indexing → ai_markdown_progress；写操作统一经 preflight.ts 预检 + Store/WAL 原子写入，读操作经 scope 校验后访问 group-index.json。
- mcp-tools 下的 mcp-http.ts/mcp-http-api.ts/mcp-stdio-lock.ts/mcp-token.ts 将上述能力注册为 MCP 工具，形成 CLI 与 MCP 双入口共享同一业务逻辑的架构，MCP 进程停止由 mcp-stop.ts 通过 SERVICE_NAME 单例识别。
- 辅助文件 chunker.ts、relation-map.ts、net-addr.ts、path-search.ts、wal.ts、progress.ts、cli-args.ts 在各子模块间横向复用，构成统一的底层设施。
