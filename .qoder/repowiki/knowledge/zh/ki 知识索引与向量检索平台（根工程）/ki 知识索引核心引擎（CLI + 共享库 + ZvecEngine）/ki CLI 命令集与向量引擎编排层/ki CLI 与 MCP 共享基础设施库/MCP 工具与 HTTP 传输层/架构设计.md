模块按职责划分为四层：
- 工具层（`src/lib/mcp-tools/*.ts`）：每个文件对应一个 MCP tool（如 `store.ts`、`search.ts`、`bulk-store.ts`、`sync-relation.ts` 等），通过 `server.tool(name, schema, handler)` 注册；所有处理器统一用 `util.ts` 中的 `withTimeout` + `TOOL_TIMEOUT.{READ,WRITE,BULK}` 预设包裹底层执行，避免长驻进程被向量库/embedding 阻塞。
- 传输与路由层（`mcp-http.ts`）：基于 `@modelcontextprotocol/sdk` 的 `StreamableHTTPServerTransport` 在 Node `http.Server` 上实现 `/mcp` JSON-RPC 会话，维护每会话 transport Map、空闲回收定时器、最大会话数保护；`/healthz` 免鉴权用于单例探活；`/api/*` 通过延迟 `dynamic import('./mcp-http-api.js')` 加载，提供 health/tags/doc/list/import/upload/run/status 等 REST 接口。
- 鉴权与授权层（`mcp-token.ts`）：持久化 `~/.ki/mcp-tokens.json`（0600），支持多 Token、每个 Token 绑定 scope 集合（含 `all` 通配），提供 `createToken/updateTokenScopes/deleteToken/findTokenScopes/tokenCount`；`mcp-http.ts` 中 `findScopeViolation` 对每个 `tools/call` 做前置 scope 越权校验，白名单 `SCOPE_LESS_TOOLS`（`ki_scope_list`、`ki_manage_index_list`）交由工具层按 `authScopes` 过滤输出。
- 进程管理层（`mcp-stdio-lock.ts`、`mcp-stop.ts`、`mcp-http.ts` 中的 lock 写入）：stdio 模式使用 `~/.ki/mcp-stdio-<pid>.lock` 多实例登记，HTTP 模式写 `~/.ki/mcp-http.lock`；`stopMcpInstances` 从 stdio lock、http lock、`/healthz` 三者收集目标 PID，先 SIGTERM 优雅退出再超时 SIGKILL 兜底，并清理残留 lock。
依赖方向单向：`mcp-http.ts` → `mcp-http-api.ts` → 各工具层；`mcp-stop.ts` 仅依赖 lock 与 http 探活，不反向引用工具。
