- 每个 MCP 工具独立一个文件并通过 `server.tool(name, zodSchema, async handler)` 注册，handler 内部统一用 `withTimeout(..., TOOL_TIMEOUT.X, name)` 包裹底层调用。
- 鉴权路径一律通过 `isLoopbackAddr`/`isLoopbackHost` 判断来源地址，回环来源免 Bearer Token，非回环来源强制校验 `Authorization: Bearer` 头并使用 `timingSafeEqual` 比较。
- scope 越权校验集中在请求入口（`mcp-http.ts` 的 `findScopeViolation` 与 `mcp-http-api.ts` 的路由分支），拒绝时服务端 stderr 记录具体 scope 但响应体脱敏，防止枚举探测。
- 进程状态通过 `~/.ki` 下的 lock 文件登记（stdio 为 `mcp-stdio-<pid>.lock`，HTTP 为 `mcp-http.lock`），读取时做 pid 存活校验并自动清理陈旧锁。
- 对外暴露的函数采用「构建器 + 工厂」模式（如 `createMcpHttpServer`、`buildServer(authScopes)`），便于测试注入 `resolveClientAddr`、`resolveTokenScopes` 等依赖。
- 所有落盘写操作（token 存储、import 上传目录）均先创建受限目录/临时文件再原子 rename，失败时清理残留并返回结构化错误对象 `{ ok, error, code? }`。
