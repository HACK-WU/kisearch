模块以 `index.ts` 为唯一对外门面，仅导出 `ZvecEngine`、公共类型与 `SiliconFlowProvider`，Embedding/Worker 系列标记 `@internal` 不暴露。
- 入口编排：`engine.ts` 中的 `ZvecEngine` 类封装静态工厂 `create/open/tryOpen/probe`，负责配置校验（`schema/validator.ts`）、Schema 构建（`schema/builder.ts`）、Embedding 批处理（按 `EMBED_BATCH_SIZE=64` 切分并去重）、Filter 编译（`filter/compiler.ts` 产出 zvec 类 SQL 字符串）、搜索路由（`search/router.ts` 根据 queryText/vector/fts 退化到 vector/fts/hybrid 三路），最终通过 `proxy.send` 下发。
- 进程隔离：`proxy.ts` 的 `ZvecEngineProxy` 用 `node:worker_threads` 启动独立 `worker.ts`，维护状态机 `init→opening→open→closing→closed/crashed/failed`，通过 `postMessage` + 自增 id 关联 Promise；`worker.ts` 持有唯一 `ZVecCollection` 句柄，串行处理消息，写路径分批调用 `upsertSync/insertSync/updateSync` 并在每批间 `setImmediate` 让出事件循环以便查询插队。
- 协议层：`worker-protocol.ts` 定义跨线程消息结构（`WorkerRequest/WorkerResponse`、各 payload 类型）以及错误序列化/反序列化机制，配合 `errors.ts` 中 `ERROR_CONSTRUCTORS` 映射实现跨线程异常重建。
- 依赖方向：`engine → {proxy, embedding/provider, filter/compiler, search/router, schema/*} → types/errors`；worker 侧反向依赖 `schema/builder` 与 `@zvec/zvec` 原生绑定，不引用主线程代码。
- 生命周期：`probe` 通过带超时的临时 proxy 探测集合是否存在/被锁/损坏；`close` 先 drain 在途请求再 `closeSync` 释放 LOCK，`destroy` 走 `ZVecDestroy` 彻底删除集合文件。
