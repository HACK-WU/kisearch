- 每个测试文件通过 `before/after` 钩子在临时目录中创建/清理 scope 数据，并使用 `cleanupScope()` 删除 `kb/{scope}` 目录与 `{scope}.json` 标记文件。
- 测试通过 `registerTestScope()` 将随机 scope 名写入进程级临时 `config.json`，再经由 `getTestEnv()` 传递给子进程，确保 CLI 子进程读取同一份测试配置。
- zvec-engine 相关测试统一从 `zvec-engine-fixtures.mjs` 引入 `mockEmbedding`、`makeConfig`、`makeDbPath`，以固定维度 4096 和 COSINE 指标构造集合，避免触网。
- 端到端网络测试文件以 `.network.mjs` 结尾，通过 `execFileSync('npx', ['jiti', 'src/...'], { env: getTestEnv() })` 调用 CLI 入口，断言 stdout JSON 的 `ok/stats/groups/source` 字段。
- 测试夹具与数据分离：可复用的夹具放在 `test/` 根目录（如 `test-config.ts`、`zvec-engine-fixtures.mjs`），静态测试数据放在 `test/fixtures/` 与 `test_data/`，运行时生成数据一律落盘到 `os.tmpdir()` 或 `.e2e-run/`。
- 敏感信息（embedding API Key）仅通过环境变量注入，测试配置文件本身不写死密钥，未注入时向量化能力显式失败以便用例跳过。
