模块由两个并列的独立探针组成，分别面向 Python 与 Node.js 运行时：
- `zvec-probe/`：基于 PyPI 包 `zvec`，通过 `CollectionSchema` + `FieldSchema`/`VectorSchema` 定义 schema，使用 `create_and_open`/`open` 管理集合生命周期；内置轻量词哈希 bag-of-words embedding（DIM=256），并通过 RRF（Reciprocal Rank Fusion）在进程内融合稠密向量与 FTS 两路结果。
- `zvec-probe-node/`：基于 npm 包 `@zvec/zvec` v0.5.0，使用 `ZVecCreateAndOpen`/`ZVecOpen` 等原生 API，除 RRF 外还额外调用 `multiQuerySync(rerank:'rrf')` 验证引擎原生混合检索路径。
两者共享相同的业务语义（模拟 kisearch 的 relation/search/path 三类文档、tag/scope/content 字段、COSINE HNSW dense + BM25 FTS + tag 过滤），数据目录均落在系统临时目录以避免污染工作区；`zvec-probe/.mem-cmp/lancedb/` 与 `zvec-probe-node/mcp_live_kb/` 为运行期产生的 LanceDB/RocksDB 持久化存储，非源码。
