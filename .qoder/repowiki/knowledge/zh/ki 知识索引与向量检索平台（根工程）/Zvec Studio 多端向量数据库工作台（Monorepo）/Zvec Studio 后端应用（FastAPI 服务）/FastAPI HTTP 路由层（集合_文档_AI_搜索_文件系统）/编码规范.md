- 每个业务域文件定义一个 `APIRouter(prefix=..., tags=[...])` 并在 `__init__.py` 中以 `<name>_router` 形式统一导出。
- 通过局部 `_get_backend(request)` / `_get_config_store(request)` 函数从 `request.app.state` 取出共享服务，再以 `Depends(_get_backend)` 注入到 handler。
- 对集合名进行二次解析时使用统一的 `_resolve(backend, name, path)` 模式，将用户传入的 name+path 回查为 SDK 内部规范名称后再转发。
- 资源级动作采用 `{resource}:{action}` 形式的自定义动词路由（如 `:flush`、`:optimize`、`:destroy`、`:browse`、`:upsert`、`:embed`、`:rerank`）。
- 请求参数使用 `Annotated[..., Path(min_length=1)]` 或 `Query(default=None)` 显式声明，避免隐式类型推断。
- 所有入参/出参均通过 `zvec_studio.schemas` 中的 Pydantic 模型进行校验，handler 内只做薄包装并直接返回模型实例。
