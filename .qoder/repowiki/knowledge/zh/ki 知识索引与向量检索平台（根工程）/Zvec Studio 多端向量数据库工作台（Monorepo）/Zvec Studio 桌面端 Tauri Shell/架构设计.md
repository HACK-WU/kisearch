模块采用「Rust 壳 + Python sidecar + Web SPA」三层结构：`src-tauri/src/main.rs` 仅做入口转发，核心逻辑在 `lib.rs` 中通过 `tauri::Builder` 构建应用、注册 `sidecar_status` / `sidecar_url` 两个 invoke 命令（`commands.rs`），并通过 `AppState`（含 `Mutex<Option<SidecarHandle>>`）在 run-loop 中监听 `CloseRequested`/`Exit` 事件以优雅关闭 sidecar。`sidecar.rs` 是纯 std 实现的进程管理模块，负责根据环境变量（`ZVEC_PYTHON`/`ZVEC_HOST`/`ZVEC_PORT`/`ZVEC_BACKEND_DIR`/`ZVEC_READY_TIMEOUT_SECS`/`ZVEC_SIDECAR_DISABLED`/`ZVEC_SIDECAR_BINARY`）决定以 `python -m zvec_studio.cli` 还是 PyInstaller 冻结二进制方式启动后端，并通过 TCP 轮询等待 uvicorn 就绪；端口冲突时调用平台工具（`lsof`+`kill` 或 `netstat`+`taskkill`）清理残留进程。前端由 `tauri.conf.json` 指向 Vite dev server (`devUrl: http://127.0.0.1:5173`) 或构建产物 (`frontendDist: ../../frontend/dist`)，通过 `/api/v1/*` 直接访问 sidecar。打包阶段通过独立的 `tauri.bundle.conf.json` 注入 `externalBin`，避免开发构建因缺少 host-triple sidecar 而失败；release profile 启用 LTO、strip、opt-level=s 以缩小体积。测试分两层：Rust 侧 `packaging_tests.rs` 与 `sidecar.rs` 内 `#[cfg(test)]` 覆盖生命周期，前端 E2E 使用 WDIO (`wdio.installed.conf.mjs`) 验证已安装应用。
