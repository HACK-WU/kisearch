模块按 `features/collections`（数据层）与 `pages/collections`（UI 层）两层组织：
- 数据层 `api.ts` 通过 `createCollectionsApi(client)` 工厂将后端 `/collections/*` REST 端点映射为扁平方法（list/get/create/open/remove/flush/optimize/destroy/字段与索引 CRUD/recent），类型全部来自 `@zvec-studio/api-client` 的 `components['schemas']`；`hooks.ts` 基于 `@tanstack/react-query` 为每个方法暴露一个 `useXxx` hook，统一通过 `useApiClient()` 注入传输并维护 `collectionsQueryKey`、`collectionDetailQueryKey`、`recentCollectionsQueryKey` 等常量 query key，在 mutation 成功后调用 `invalidateCollection` 或 `qc.invalidateQueries` 刷新列表与详情缓存。
- UI 层以 `CollectionDetailPage` 为入口，根据 URL 参数 `tab` 切换 overview/browse/query/write 四个 Tab，每个 Tab 是独立子组件（如 BrowseTab、QueryTab、MutateTab、OverviewTab），并通过共享的 DocumentsPanel、SearchPanel、FilterBuilder、SchemaDdlSection 等可复用面板组合而成；CreateCollectionDialog、OpenCollectionDialog、InsertDocumentDialog 作为弹窗复用。
- 工具函数集中在 `coerce-field-value.ts`（按 schema dataType 把字符串输入转为 JS 数值/布尔/数组）和 `vector-utils.ts`（dense/sparse 向量解析、格式化、随机生成、嵌入函数匹配），被多个页面组件引用。
- 依赖方向单向：pages → features/hooks → features/api → `@/lib/api-client`；feature 不反向依赖任何页面。
