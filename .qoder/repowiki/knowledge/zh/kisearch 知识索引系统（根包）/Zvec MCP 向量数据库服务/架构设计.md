模块以 `src/zvec_mcp/server.py` 为唯一入口，通过 `FastMCP('zvec_mcp')` 实例注册所有 MCP Tool 与 Resource（如 `create_and_open_collection`、`vector_query`、`zvec://collections` 等），并由 `__main__.py` 暴露 `python -m zvec_mcp` 及 `pyproject.toml` 中 `[project.scripts]` 的 `zvec-mcp-server` 命令行。

内部按职责划分为四个子文件：
- `schemas.py`：集中定义全部 Pydantic v2 输入模型（`CreateCollectionInput`、`DocumentInput`、`VectorQueryInput`、`MultiVectorQueryInput` 等），并使用 `Annotated[..., Field(discriminator='type')]` 实现 HNSW/Flat/IVF/Invert 索引参数的多态判别。
- `types.py`：声明共享枚举（`ResponseFormat`、`DataTypeEnum`、`MetricTypeEnum`、`QuantizeTypeEnum`、`IndexTypeEnum`），被 schemas 与 server 共同引用。
- `utils.py`：维护进程内全局 `_open_collections: dict[str, zvec.Collection]` 作为会话级缓存，并提供 `get_collection`/`cache_collection`/`remove_collection_from_cache`、类型转换（`get_zvec_data_type`、`get_zvec_metric_type`、`get_zvec_quantize_type`）、统一错误格式化 `handle_error` 以及 Markdown/JSON 双格式输出 `format_doc_list`。
- `server.py`：业务编排层，将 Pydantic 参数转换为 `zvec.*` SDK 对象并调用底层集合操作；索引参数通过内部 `_build_zvec_index_param` 分派到对应 `zvec.*IndexParam`。

依赖方向单向：`server → schemas + utils + types`，`schemas → types`，测试 `tests/test_server.py` 直接 import 各函数进行端到端验证，使用 pytest-asyncio 的 `@pytest.mark.asyncio` 类组织用例。构建系统采用 hatchling + hatch-vcs 动态版本，ruff 校验 E/F/I/N/W/UP 规则，pytest 配置启用 `asyncio_mode = auto`。
