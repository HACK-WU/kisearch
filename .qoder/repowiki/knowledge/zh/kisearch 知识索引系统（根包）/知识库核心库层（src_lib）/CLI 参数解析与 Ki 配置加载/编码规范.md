- 配置字段校验采用声明式 `ConfigNode` 树（type + fields/value/nullHandling/deprecated/validate）而非硬编码 if-else，新增字段只需扩展 schema 节点。
- 未知 CLI 参数与未知配置字段均通过 Levenshtein 编辑距离计算最接近候选项，并以「您是否想输入 X？」形式给出友好建议。
- 错误输出统一遵循 `{ ok: false, error, code? }` JSON 契约（`failJson`/`toErrorPayload`），并将诊断信息写入 stderr，stdout 保持结构化输出。
- 配置加载结果在进程内以 `_cached` 单例缓存，首次调用后重复读取直接返回，测试场景通过 `resetConfigCache` 清除。
- 可选配置字段采用「未提供则走内置默认值」的归一化策略（如 `scopeMode` 非法值归为 `'default'`、embedding 各字段分别 fallback 到 `DEFAULT_EMBEDDING`）。
- 对已知废弃字段采用「只告警不阻断」策略（`deprecated` 映射 + warn 通道），保证存量配置仍可加载并提示迁移路径。
