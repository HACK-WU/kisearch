模块按职责分为四层：
- 传输与进程守护层：`mcp-http.ts` 基于 Node `node:http` + `@modelcontextprotocol/sdk` 的 `StreamableHTTPServerTransport` 构建 MCP HTTP 服务，提供会话生命周期管理、空闲回收、DNS rebinding 保护、`/healthz` 探活与 `--web` 静态页面；通过 `probeHealthz` + `~/.ki/mcp-http.lock` 实现幂等单例，避免多 IDE 同时持锁冲突。
- API 扩展层：`mcp-http-api.ts` 延迟加载，挂载 `/api/health`、`/api/doc/list`、`/api/tags`、`/api/import/upload|run|status` 等 MCP 缺失能力，复用同一鉴权与 scope 校验逻辑。
- 鉴权与令牌层：`mcp-token.ts` 维护 `~/.ki/mcp-tokens.json` 多 Token 存储（原子写、0600），提供 `createToken/updateTokenScopes/deleteToken/findTokenScopes`，并以 `ALL_SCOPES='all'` 表示全权；`mcp-http.ts` 在回环绑定免鉴权、非回环强制 Bearer Token，并按 Token 解析授权集合做 tools/call 级 scope 越权拦截。
- 进程锁与停止层：`mcp-stdio-lock.ts` 以每 pid 独立 lock 文件（`~/.ki/mcp-stdio-<pid>.lock`）登记 stdio 实例，支持陈旧锁自动清理与存活探测；`mcp-stop.ts` 聚合 stdio/http lock 与 healthz 结果定位目标进程，经 `/proc/<pid>/cmdline` 校验后 SIGTERM→SIGKILL 优雅关闭并清理残留 lock。
- MCP 工具层：`src/lib/mcp-tools/` 下每个文件注册一个 `server.tool(...)`，统一使用 Zod 定义参数 schema（含 `scope` 默认 `'default'`）、通过 `withTimeout` 包裹底层调用（READ/WRITE/BULK 三类超时预设），并通过 `util.ts` 暴露 `ToolTimeoutError` 与超时封装。工具仅依赖业务执行函数（如 `executeSearch`、`executeStore`），不直接操作网络或文件系统，保持纯工具语义。
