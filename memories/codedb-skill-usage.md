# codekb-skill 使用场景

**遇事不决 ki-search。** 遇到任何不知道的问题、不知道的信息、不确定的内容，**不要自己猜，直接上 ki-search 查**。

**代码相关问题同样先 ki-search。** 遇到代码相关的任何问题——代码在哪、功能怎么实现、架构、API、bug、审查——**一律先查 ki-search，因为记忆里很可能已有这段代码的相关知识**（踩坑点、关键逻辑、工具函数等）。先看有没有现成知识，再看代码，不要一上来就 grep/读文件。

方向：问题 → 知识（正查）。不知道代码在哪、想知道功能怎么实现时，正查代码知识。

典型场景：了解模块职责、查架构决策、理解设计约束、查 API 接口、排查 bug、代码审查，以及任何"我不知道 / 我拿不准"的场景。

> 核心原则：**宁可先搜，不要先猜。** 凡是自己不确定的，一律先 `ki_search` 检索，检索不到再回问用户。代码问题也不例外。
