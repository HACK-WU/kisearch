# AGENTS.md - AI AGENT 项目记忆文件

## 🔑 第一原则：遇事不决，ki-search

**遇到任何不知道的问题、信息或不确定的内容，先用 `ki_search` MCP 工具查项目记忆，不凭记忆猜、不凭印象答。**

- 查询顺序：先 `ki_search(scope: "${scope}-memory", ...)` 查项目上下文与决策；确认主题在代码库时再查 `${scope}`（代码知识）。**项目已有既定检索口径时以项目为准**，不要按模板强行改写
- **该看视图的两个信号**：① 单库 `ki_search` 结果不足或文不对题；② 问题横跨多域（代码 + 运维 + 专家经验 + 项目决策）。命中时先 `ki_view_list()` 找现成聚合视图；**没有合适视图时**再显式拼多段 scope（`ki_search(scope: "a,b", ...)`，勿长期硬拼）。视图是多个库的**只读**聚合，**视图名可直接当 scope** 传给 `ki_search` / `ki_group_list` / `ki_tag_list` / `ki_get_module_info`。**成员含 `${scope}`、`${scope}-memory` 或 `${scope}-*` 同词根的视图才与本项目相关**，其余忽略；本文件**不缓存视图列表**（会变），每次实时查。同时看 `usableCount / availableCount` 与 `degradedReason` —— 有降级说明时部分成员不参与语义检索。**`threshold` 量级不同**：单库 `0.02~0.03`、视图（多库）`0.6~0.8`，混用会全灭或全留
- **视图只读**：写入（`ki_sync_relation` / 上传文档）必须用真实库名，用视图名会被拒
- 同源约定：`rules/ai-codekb-memory.md`「第一性原则：遇事不决 ki-search」

## 📝 第二原则：主动沉淀，不等提示

**开发 / 设计 / 排查过程中产生的信息、决策、设计，AI 自己写进 ki 的 `${scope}-memory`，不等用户说"记录一下"。**

> 用户开口不是触发条件。**真正的触发条件是「这条结论将来还有人要用」**——换个会话、换个人接手还能省掉一次重复调研，就当场写；不写会导致重新调研 / 重新问人 / 重新踩一遍坑，就当场写。
> 不允许"先干活、收尾统一补记"：收尾补记会被截断、被遗忘、被压成一句话而丢掉细节。

- **沉什么、落哪个 Group**：选型与取舍 → `决策记录`；架构分层与模块职责 → `项目架构`；数据流与字段口径 → `数据流`；接口契约与错误码 → `接口信息`；报错根因与解法 → `错误库` / `项目踩坑点`；模块用法与实现要点 → `专题记忆/{模块名}`；团队约定 → `团队约定`；外部依赖限制 → `外部依赖`；可复用工具函数 → `工具库`；项目阶段与当前状态 → `当前状态`；都不合 → `通用记忆片段/{分类}`
- **写前必查重**：`ki_get_module_info` 取回正文 —— `ki_sync_relation` 是**整篇覆盖、无追加语义**，同主题**改**，不同主题才**新建**；单条用 `ki_sync_relation`，**≥3 条用 `ki_bulk_sync_relation`**（每批 ≤5）；单篇正文控制在 1000 字符内，超长拆 Relation
- **写后两步**：① 按 `ki_group_list(mode: "full")` 刷新本文件「项目记忆索引」（写的是「团队约定」组时同时回刷本文件「团队约定」章节）；② 在「近期工作」记一行 `- [YYYY-MM-DD] {一句话}`（≤ 80 字）
- **不写**：用户画像与需求进度（只进本文件）、一次性试错与中间状态、敏感信息（用占位符）、`${scope}` 代码知识库（默认只读，需用户明确授权）
- **库名未定时**：以本文件「项目记忆索引」首行登记的 `${scope}-memory` 为准；项目尚未初始化（无索引章节 / 无 memory scope）→ 先走 `agents-md-init` 引导，**不臆造 scope 名**
- **两条通道（沉淀 ≠ 只写 relation）**：正文已在上下文里的一条结论 → `ki_sync_relation`；**本地已写好的成篇文档（设计文档 / 方案 / 排查报告 / 调研报告，几百行乃至 500+ 行）→ `use_skill("ki-upload")` 直接上传**，别塞进 relation（>1000 字符会警告、检索质量差，手工复制也易错），也**不必先摘要再写**——原文上传，摘要只留「近期工作」一行；上传落组必须含 `文档` 段（如 `专题记忆/{模块}/文档`、`错误库/文档`），详见「知识文档入库」章节

## 项目记忆索引

> 数据来源：ki 的 `${scope}-memory` scope（`YYYY-MM-DD` 初始化）。仅缓存此 scope，代码知识库不缓存。
> **转写规则**：下面的 Group 结构与热门 Relation 必须由 `ki_group_list` 输出**逐行机械转写**，禁止读完凭印象重写（会持续漂移）。

### {scope}-memory 索引

#### Group 骨架（按需补建，不必一次建满）

只立即建**必要项**，其余等 `ki_sync_relation` 写入时自动补建（该工具会自动创建路径上缺失的所有节点）：

```text
ki_group_create(scope: "${scope}-memory", path: "团队约定")
# scope 不存在时该工具自动创建并返回 createdScope，无需单独建 scope
```

| Group | 必要性 | 用途 |
|-------|--------|------|
| 团队约定 | **必建** | 「团队约定」章节的同步源（见本文件「团队约定」章节） |
| 背景与目标 / 当前状态 / 项目架构 | 建议 | 高频读写，先有槽位便于归类 |
| 技术栈选型 / 项目历史 / 外部依赖 / 项目踩坑点 / 工具库 / 常用命令 / 部署运维 | 按需 | 首次写入时自动补建 |
| 接口信息 / 数据流 / 决策记录 / 关联关系 | 按需（**高频，建议预留**） | 实测多个项目都会自发演化出这四类 |
| 专题记忆 | 按需 | **必须先建子组再写 Relation**（团队约定，系统不校验） |
| 通用记忆片段 | 兜底 | 无法归入上述分类时用，可再按功能/类型细分子组 |
| 错误库 | 可选 | 踩坑多的项目适用；不需要就别建 |

## 团队约定

> **同步源**：ki `${scope}-memory` → 「团队约定」Group（`ki_group_list(scope: "${scope}-memory", groups: "团队约定", mode: "full")`）。
> **本节为缓存**：权威数据在 ki，此处只做占位同步，便于 agent 免查询直接获取。
> **无内容时必须写 `无`**，禁止留空或删除本节；写入 ki 后须回刷本节。
> **写入方向**：先 `ki_sync_relation(scope: "${scope}-memory", group: "团队约定", ...)`，再把要点回刷到本节。

- 无

## 知识文档入库

> **运行期约定**：开发 / 设计 / 排查过程产出**可复用**文档时，按此入库，让下次会话直接检索到。
> **判据**：换个会话、换个人，这份文档能不能省掉一次重复调研？不能就不传。
> **该传**：设计文档、需求报告、排查结论、调研报告、上线手册 ｜ **不传**：源码、临时草稿、日志、原始证据。

- **落点**：上传到 `${scope}-memory`；`--group` 必填且**路径里要有一层 `文档`**（如 `专题记忆/{模块}/文档`、`错误库/文档`）——索引据此机械折叠，别改名
- **通道**：本机文档 → `use_skill("ki-upload")` 的 `upload` / `upload-dir`；正文已在上下文里的短内容 → `ki_sync_relation`
- **上传后**：`ki_search(scope: "${scope}-memory", query: "<文档里的一句话>")` 命中或 `ki_group_list` 能看到该 relation 名才算入库，然后在「近期工作」记一行
- **缺能力时**（Python / httpflex / `KI_URL` / `KI_TOKEN`）：打印可执行命令让用户自己跑，**不阻塞、不报错**

## 近期工作 (7天内)

> **每条严格 1 行（≤ 80 字）**：只写结论；根因、代码位置、验证数据、审查过程写入 `${scope}-memory` 或项目台账（`.plans/`、`.debug/`），此处最多留一个指向。
> **容量**：目标 ≤ 20 条 / ≤ 40 行。**每次追加新条目后就数一次**，> 20 条则本次立即归档（不等下次访问才想起）。
> 状态标记：`🔄` 进行中 / `✅` 已完成 / `🆕` 待拍板。

- [YYYY-MM-DD] ✅ {一句话结论}
- [YYYY-MM-DD] 🔄 {一句话进度}
